# 06 — Jobs, notebooks, and dbutils

## Runtime strategy

Replace Spark-oriented job launching with a BrickHouse supervisor and fresh Python worker. Reuse selected Minilake task validation/lifecycle ideas only after adapting them to persistent instance-scoped state. The worker gets a run ID, attempt ID, profile, parameters, namespace, environment reference, workspace mapping, cancellation channel, and run-scoped internal credential.

Use the resolved environment's interpreter, not an unqualified `python3` from PATH. Initially require the current supported BrickHouse environment. Later environment specifications can create cached virtual environments from locked dependencies. Do not automatically run arbitrary library installation requests from a cluster configuration.

**B013 implementation:** `brickhouse.runtime.run_python_worker()` resolves the selected interpreter and script to absolute paths, sets an explicit working directory, disables shell execution, and snapshots JSON-only attempt context into `BRICKHOUSE_RUN_CONTEXT_JSON`. The context is capped at 16 KiB. Each child starts without inherited credentials, Python import paths, or session state. Stdout and stderr are drained concurrently with 1 MiB defaults and a 64 MiB per-stream maximum. Results contain the actual exit code, bounded text, truncation flags, limits, and resolved paths. The version-1 private message envelope is capped at 64 KiB and rejects malformed JSON, unknown fields and invalid scopes. A random per-attempt bearer is delivered only in `BRICKHOUSE_WORKER_TOKEN`; its digest is kept by the parent. Credentials are revoked after termination, and captured output redacts the token. Timeouts and cancellation signal the POSIX process group, escalate after a bounded grace period, reap the direct child, and invoke caller-supplied safe staging cleanup. Metadata schema 5 stores the real exit result and cleanup status without logs or credentials. See [ADR 0019](../decisions/0019-worker-private-authentication.md) and [ADR 0020](../decisions/0020-worker-supervision-and-outcomes.md).

**B014.1 implementation:** `WorkspaceContext.jobs` exposes an internal SQLite repository for immutable, bounded Python-script job definitions, immutable submission snapshots, workspace-wide idempotency tokens, task DAG snapshots, durable attempts, and explicit state transitions. Metadata schema 6 adds the job/run/task/attempt tables with foreign keys, content fingerprints, legal-transition and terminal-result checks, and immutable terminal history. Invalid dependencies, cycles, unsupported task kinds, credential-shaped setting keys, and changed token replays fail explicitly. Interrupted runs retain unknown exit status and do not convert pending tasks into successful work. This is a persistence contract only: it does not dispatch workers, expose SDK/HTTP routes, recover active runs automatically, return durable logs, or implement concurrency/retry policy. See [ADR 0022](../decisions/0022-durable-job-state.md) and [B014.1 evidence](../../artifacts/conformance/B014.1-durable-job-state.md).

**B014.4 implementation:** `WorkspaceContext.compute` persists simulated classic all-purpose cluster identities and run-scoped new/shared job compute in metadata schema 7. The pinned `databricks-sdk==0.153.0` loopback profile implements classic cluster create/get/list/edit/start/restart/terminate/permanent-delete. Standard/dedicated access labels and the `spark35-local-v1` alias are explicit local mappings; unmapped Databricks Runtime strings, access modes, Photon, JVM-specific settings, policies, and cloud-specific effects fail explicitly. A controlled clock drives idle termination. Consumers register before dispatch, shared compute starts for the first consumer and stops after every planned consumer releases, while all-purpose identity survives termination and can autostart when requested. Generation numbers and append-only events record session invalidation. These records do not allocate compute, enforce access isolation, or execute workers. See [ADR 0023](../decisions/0023-local-classic-compute-lifecycle.md) and [B014.4 evidence](../../artifacts/conformance/B014.4-classic-compute-lifecycle.md).

**B014.5 implementation:** `ExecutionContextResolver` maps the pinned task wire shapes to immutable internal context before dispatch. It accepts Python script/notebook tasks with normalized `/Workspace/...` paths, declared serverless environment version `1` and installed dependency pins, or classic inline/shared/existing compute. It records run/task identity, profile, resource ID/key/generation, task arguments, timeout, retries and effective settings. Serverless tasks require `disable_auto_optimization=true` and receive ANSI/UTC defaults. Unmapped clients/versions/dependencies, installs, compute objects, conflicting selectors, unsupported conditions/task types, SQL warehouse notebooks, credential-shaped parameters and invalid paths fail explicitly. An omitted or zero timeout means no timeout; positive values use the local worker's 24-hour maximum. This slice does not check file existence, upload files, dispatch a child, schedule retries, or claim workload compatibility. See [ADR 0024](../decisions/0024-pre-dispatch-execution-context.md) and [B014.5 evidence](../../artifacts/conformance/B014.5-execution-context-resolution.md).

**B014.2 implementation:** the pinned `databricks-sdk==0.153.0` loopback routes accept SDK multipart workspace imports (`SOURCE`/`PYTHON`) under normalized `/Workspace/.../*.py` paths and persist source bytes atomically under the owned workspace `files/` directory. Imports are capped at 1 MiB. Job tasks use resolved local serverless/classic selectors and mapped environments; `/run-now` submits saved parameters or bounded single-task `python_params`. Idempotency tokens replay the same run while it is active or terminal. `/runs/get` maps observed local state to SDK lifecycle/result enums; `/runs/get-output` returns at most 1 MiB stdout and 1 MiB stderr (`logs`/`error`) with truncation metadata for a single-task run. Metadata schema 8 stores immutable attempt output and validates upgrades from schema 7. B014.3.2.1 adds retry policy, and B014.3.2.2 adds bounded concurrency admission; output for multi-task runs and output while running remain unsupported. Each fresh child process runs plain Python with a minimal environment and immutable run context; B014.6 now binds classic worker starts/stops to simulated resource lifetimes. Workers still have no `spark` session or job-facing Delta table API; no cloud compute or Databricks runtime parity is claimed. See [ADR 0025](../decisions/0025-sdk-python-job-flow.md) and [B014.2 evidence](../../artifacts/conformance/B014.2-workspace-files-sdk-jobs.md).

**B014.3.1 implementation:** the service accepts up to ten validated Python script tasks and dispatches them sequentially in a stable topological order. The repository independently refuses to queue an attempt until every dependency succeeded. Failed, cancelled, skipped, or interrupted dependencies produce a persisted `SKIPPED` task with zero attempts; independent tasks continue, and the run is failed after all eligible work has a truthful terminal outcome. Only default `ALL_SUCCESS` scheduling is supported. B014.3.2.1 adds bounded task retries; B014.3.2.2 admits concurrent runs within a local process limit. B014.3.3 reconciles active runs after service restart. Multi-task output retrieval remains unsupported, and this dispatch path does not provide Spark/Sparkless or job-facing Delta effects. See [ADR 0026](../decisions/0026-sequential-job-dag-dispatch.md) and [B014.3.1 evidence](../../artifacts/conformance/B014.3.1-dag-dispatch.md).

**B014.3.2.1 implementation:** validated task retry settings are now executed as a bounded local policy. Nonzero worker exits retry up to ten times, timeout retries require `retry_on_timeout=true`, and `min_retry_interval_millis` is honored with an interruptible wait. Each attempt has a distinct durable identity and immutable output. Launch failures, cancellation, and interrupted attempts do not retry. The API reports initial/retry attempts using the SDK's zero-based attempt number while persisted attempt numbers remain one-based. `max_concurrent_runs` admission is still B014.3.2.2. See [ADR 0027](../decisions/0027-bounded-task-retries.md) and [B014.3.2.1 evidence](../../artifacts/conformance/B014.3.2.1-retry-attempts.md).

**B014.3.2.2 implementation:** each job accepts `max_concurrent_runs` from 1 through 4, and the process admits at most four worker runs across all jobs. Admission and active token replay checks run under one service lock; active and terminal token replays return their original run before capacity checks. Capacity rejects with HTTP 409 (`RESOURCE_CONFLICT`) before run creation so the SDK does not retry the request. Restart reconciliation remains B014.3.3. See [ADR 0028](../decisions/0028-bounded-run-admission.md) and [B014.3.2.2 evidence](../../artifacts/conformance/B014.3.2.2-run-admission.md).

**B014.3.3 implementation:** metadata schema 9 stores each worker PID and accepts an explicit interrupted outcome with no exit code. On service start and when a run is polled, the local job service checks persisted active attempts. If the worker PID is gone, it preserves already completed attempts and output, marks unknown in-flight worker and job attempts interrupted, and reports `WORKSPACE_RESTARTED`; it does not replay user code. If an orphan worker is still alive, the service leaves the run active and reconciles it after a later poll observes that process has exited. SDK output retrieval falls back to the latest attempt with persisted output if the current attempt was interrupted before capture. No cross-process worker adoption or replay guarantee is claimed. See [ADR 0029](../decisions/0029-active-job-restart-reconciliation.md) and [B014.3.3 evidence](../../artifacts/conformance/B014.3.3-active-run-recovery.md).

**B014.6 implementation:** each submitted classic job reserves planned consumers for its run. Immediately before a task, new/shared resources start for that consumer; an existing all-purpose cluster retains its ID and autostarts when explicitly resolved as terminated. Each worker receives the actual simulated resource ID, generation and state alongside its immutable per-attempt context. Task results release consumers; failed dependencies and service recovery also release reserved consumers, and the last released new/shared consumer terminates the resource. A monitor checks the selected all-purpose generation/state while user code runs. Restart or termination increments/changes the resource state, signals worker cancellation, and the worker supervisor terminates and reaps the POSIX process group. The pinned-SDK loopback corpus exercises all seven document 16 job variants, restart and termination during real work, service recovery without inferring success, and preservation of an already committed Delta table. Compute allocation remains simulated, and workers still cannot read/write tables or receive Spark/Sparkless sessions. See [ADR 0030](../decisions/0030-job-worker-compute-lifetimes.md) and [B014.6 evidence](../../artifacts/conformance/B014.6-job-worker-compute-lifetimes.md).

**B016.1 implementation:** every SDK Python task is launched through a small worker entry module that injects a fresh `dbutils` object into that script's global namespace. `dbutils.fs` maps `dbfs:/...` and `/dbfs/...` to `workspace/files/dbfs`, with symlink and parent-traversal rejection. `ls`, `head`, `put`, `cp`, `mv`, `rm`, and `mkdirs` perform real local operations; previews, writes, and recursive tree operations have explicit size/entry limits. `dbutils.widgets` supports text/dropdown/combobox/multiselect declarations, get/getAll and removal. Widget values start from defaults, then `name=value` task parameters, then matching run-now `python_params`; ordinary argv entries remain unchanged for the script. The state is constructed in each fresh worker, so declarations and values do not cross runs. Other filesystems, mounts, volumes, notebook utilities, and arbitrary dbutils methods are not provided. Direct Python filesystem access remains trusted code and is not sandboxed. See [ADR 0031](../decisions/0031-worker-dbutils-files-and-widgets.md) and [B016.1 evidence](../../artifacts/conformance/B016.1-worker-dbutils-files-widgets.md).

**B016.2 implementation:** `WorkspaceContext.secret_provider` holds explicit scope values and per-job scope grants in process memory only. An embedding caller configures values with `put(scope, key, value)` and authorizes a job with `grant_job(job_id, scope)`; these APIs do not persist values or grants, read `.env`, or accept public HTTP credentials. At each task attempt, the service snapshots only that job's granted scopes and sends the bounded payload to the child over a one-way stdin pipe. Values are absent from immutable worker context, run/job metadata, environment variables, command-line arguments and ordinary configuration. The worker exposes `dbutils.secrets.get/getBytes/list/listScopes`; ungranted scopes raise `PermissionError`, missing keys in granted scopes raise `KeyError`, and list methods expose only authorized scope/key metadata. Exact secret bytes are redacted from retained stdout/stderr before results are returned or journaled. Transformed/encoded values cannot be generally recognized. Values/grants are process-local and must be configured again after service restart. See [ADR 0032](../decisions/0032-process-memory-scoped-secrets.md) and [B016.2 evidence](../../artifacts/conformance/B016.2-process-memory-scoped-secrets.md).

**B016.3 implementation:** Python script workers expose `dbutils.jobs.taskValues.set/get` through a versioned, attempt-authenticated local socket to the parent repository; SQLite never opens in the child. Values must be strict finite JSON, each compact UTF-8 JSON representation is at most 48 KiB, and each run may define at most 250 distinct `(task, key)` pairs. A task can update its key within an attempt. Rows are keyed by run, task, attempt, and key; a reader can access only transitive declared upstream tasks after they succeed, and the latest successful attempt supplies the value. Failed-attempt rows remain attributable to that attempt but are not visible downstream. `get` raises `ValueError` for an unknown task or missing value unless a non-`None` `default` is supplied; `debugValue` is accepted but only applies outside a job, so it never masks a missing value in a job worker. `set` returns `True`. Unsupported `dbutils.jobs` methods raise `DbutilsOperationNotSupportedError`. This script-task adapter follows the documented task-value contract, while Databricks documents `dbutils.jobs.taskValues` for Python notebooks; notebook execution/output is still B017. Existing attempt stdout/stderr remains the captured job output after the worker exits; no notebook exit or live output API is claimed. See [ADR 0033](../decisions/0033-attempt-scoped-task-values.md) and [B016.3 evidence](../../artifacts/conformance/B016.3-attempt-scoped-task-values.md). Databricks contract references: [dbutils taskValues reference](https://docs.databricks.com/aws/en/dev-tools/databricks-utils) and [task values guide](https://docs.databricks.com/aws/en/jobs/task-values).

## Planned serverless and classic behavior

Implement both bounded job/notebook profiles under [document 17](17-serverless-and-classic-compute.md). B014.4 owns classic all-purpose and run-scoped compute records; B014.5 resolves compute selectors, environments and supported settings before worker dispatch. B014.2 owns source import and the SDK worker flow; B014.3.1 adds sequential DAG dispatch, B014.3.2.1 bounded task retries, B014.3.2.2 run concurrency admission, and B014.3.3 restart reconciliation. B014.6 binds the seven selected job contexts to actual local Python workers and simulated resource lifetimes. B017.4 binds the profiles to notebook environment precedence, attachment and reset. Keep compute/access/runtime/protocol choices in immutable context; the existing B013.1 primitive does not implement this resolution.

Serverless and classic variants must run actual Python/DataFrame work over the shared table service. Validate unsupported APIs/settings/dependencies explicitly and distinguish simulated infrastructure from worker outcomes. Fresh attempts remain isolated even when a classic job shares a compute ID; shared driver/module state is a declared incompatibility. B014.6 proves resource lifetimes against actual job workers, and B017.5 proves in-flight compute interruption with real kernels after context and cancellation primitives exist. [Document 16](16-phase-0.1-initial-release.md) enumerates seven Python and ten notebook variants and separates those checks from resource/context completion. Phase 0.2 adds selected environment/cache/access/automatic-retry behavior; phase 0.7 independently proves Connect analysis and protocol cases.

## Job lifecycle

Persist job definitions, immutable submitted settings, run/task IDs, attempt numbers, timestamps, parameters, state transitions, bounded logs/output, and error details. Validate task types and dependencies before execution. Map internal states to the pinned Databricks client's enums at the API boundary. B014.1 supplies the durable definition/submission/task/attempt metadata; B014.2 composes upload and the initial single-script SDK flow; B014.3.1 schedules bounded sequential DAGs and propagates failures; B014.3.2 implements bounded retries and local run admission. B014.3.3 still owns restart reconciliation, and B014.6 owns worker/resource lifetime behavior.

Required behavior: idempotent submission where the API provides a token, dependency validation, bounded concurrency, timeout, cancellation of the process group, process reaping, retries, and restart reconciliation. B013 provides the internal cancellation/reaping and per-attempt outcome primitives; B014 must compose them into job/run state. A terminal state is immutable except for an explicitly modeled repair/new attempt. Skipping a task because its dependency condition failed is valid; skipping an unsupported requested task as if execution succeeded is not.

Cancellation is an observable lifecycle: request stop, signal worker, escalate after grace, reap, persist terminal state. A write that already committed remains committed; cancellation must not fabricate rollback. Retry policy consults mutation idempotency records.

## Python compatibility

Explicit Sparkless imports are the first supported mode. Managed-worker compatibility can later expose selected `pyspark.sql` and `delta.tables` names through a launcher-scoped import finder/bootstrap. Preserve type identity within the worker, nested imports, aliases, and exception mappings. Track each covered namespace in capabilities.

Do not ship a top-level `pyspark` wheel that overwrites the genuine package. Do not rewrite user source with regex. Unsupported `pyspark.ml`, `rdd`, Java gateways, arbitrary jars, Scala tasks, and JVM-specific configuration must produce clear capability errors until a native equivalent is deliberately implemented.

The `delta.tables.DeltaTable` facade is a distinct compatibility task from installing `deltalake`. Map supported methods and builders into the table service, including path validation and commit IDs. Never let it create an independent unmanaged writer path for registered tables.

## dbutils implementation plan

| Surface | Proposed behavior |
|---|---|
| `fs.ls/head/put/cp/mv/rm/mkdirs` | Implemented for real local `dbfs:/` and `/dbfs/` paths under `workspace/files/dbfs`; traversal and symlinks rejected, operations bounded |
| `widgets.text/dropdown/combobox/multiselect/get/getAll/remove/removeAll` | Implemented in the SDK Python worker with defaults, `name=value` task parameters, then run-now override precedence; state is attempt-local |
| `secrets.get/getBytes/list/listScopes` | Implemented for embedding-configured process-memory values and explicit job scope grants; values cross to workers over a one-way pipe and retained raw values are redacted |
| `jobs.taskValues.set/get` | Implemented for SDK Python job scripts over the private parent service; finite JSON, 48 KiB/value, 250 distinct task/key pairs per run, attempt isolation, successful transitive upstream reads, non-`None` default, and explicit unsupported methods; not notebook parity |
| `notebook.run` | Child run using parameter scope, timeout, output contract, and parent cancellation |
| `notebook.exit` | Controlled worker signal converted to notebook output, not accidental process failure |
| Context getters | Versioned documented subset of run/job/path context |
| Mounts and credential utilities | Explicit unsupported state until meaningful native semantics exist |

The SDK's native secrets getter calls an endpoint rejected by the reviewed Minilake server. Installing the SDK does not close that gap. Inject a scoped provider into the managed runtime; never place the entire secret store in environment variables or public responses. Capture/redact secret-bearing logs and document limitations of redaction for transformed values.

## Notebook execution

Accept a documented format subset: `.ipynb` via nbformat/nbclient and Databricks Python source exports via a tested converter. Treat cell separators and magic markers structurally. Handle `%python`, `%sql`, `%md`, and `%run` through explicit handlers; reject Scala/R and unknown magics. `%run` shares notebook scope where required; `dbutils.notebook.run` creates a child invocation. Do not conflate them.

Inject `spark`, `dbutils`, and supported `display` helpers into a fresh kernel. Capture cell outputs, execution counts, errors, and notebook result artifacts. Parameterization may use Papermill, but widgets and job parameter precedence remain BrickHouse contracts. Timeout and cancellation must reach the kernel and descendants.

`%pip` and interpreter restart require environment lifecycle design; initially reject them with a clear explanation. Do not permit a notebook dependency installer to introduce Spark/JVM runtime silently.

## Minimum end-to-end job test

Use the real SDK to upload a Python script, create a job, submit it, poll it, and retrieve output. The script reads parameters and one scoped secret, builds/transforms a DataFrame, writes a managed Delta table, and returns a count. A second task reads that table by name. Validate output and data through the SQL API, then restart the server and repeat the read.

Negative cases: invalid namespace, unsupported task type, missing workspace file, bad parameter type, failing dependency, worker crash, timeout, cancellation during a write, secret access outside job scope, repeated submission token, and restart with an active run. No Java process or external compute request may occur.

Repeat the bounded workflow for serverless and classic new/existing/shared compute, with explicit environment/runtime mappings and all three local SQL warehouse types. Add pre-dispatch selector/config errors, real compute/session termination, and notebook profile variants. [Document 17's test designs](17-serverless-and-classic-compute.md#local-test-designs-and-reference-questions) define the mode-specific assertions and later cases.

## Preparation for later self-hosting

Local execution stays the emulator contract through phases 0.1–0.9. Keep PIDs, POSIX signaling, private sockets/pipes, interpreter paths and filesystem staging contained in runtime adapters; preserve durable job/attempt identity independently. B048 reviews actual boundaries using existing workload evidence. Local authorization and fresh processes do not claim authenticated network execution or sandboxing.

[Document 18](18-self-hosted-platform.md) places deployed identities/secrets in SH.1, real script/kernel/serving isolation in SH.3 and remote placement in SH.4, all after B049's stability gate. Remote attempts require enrolled/revocable workers, explicit environment/artifact identity, coordinator leases/generations validated at commits and state transitions, and truthful handling of partitions, stale completion and cancellation races. Reassignment reconciles Delta effects before replay and never promises exactly-once arbitrary Python effects. This is job distribution; a distributed Sparkless query is a separate future research decision.
