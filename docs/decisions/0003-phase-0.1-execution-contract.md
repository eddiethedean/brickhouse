# ADR 0003 — Refine phase 0.1 into bounded child tasks

Date: 2026-10-16
Status: accepted; phase 0.1 implementation is in progress, with current task state recorded in the ledger.

## Context

The owner asked to refine phase 0.1. The release roadmap assigns B001–B023 to the initial 0.1.0 alpha, but these packages span multiple implementation concerns and lack a unified minimum behavior corpus and failure checklist.

## Options

- Narrow the initial release by moving existing requirements to later versions, which requires a separate scope/dependency revision.
- Preserve the agreed alpha requirements and refine them into bounded implementation tasks with a concrete release contract.

## Decision

Preserve all original parent acceptance criteria and prerequisites. Decompose the 23 phase 0.1 packages into 68 required children in the task ledger and readable backlog. Children inherit the parent's prerequisites, may depend on earlier siblings, and identify the parent criteria they cover; none depends on its own parent. Parents complete only after children and original integration criteria pass.

[Document 16](../plan/16-phase-0.1-initial-release.md) defines internal checkpoints, minimum behaviors, a deterministic golden workflow, failure cases, prerequisite decisions, and release evidence. Child plans remain contracts to validate against actual dependencies. The next ready implementation leaf is B001.1.

## Consequences and evidence

The top-level 42 work packages and nine release phases retain their meaning. Leaf counts grow; implementation tasks and capability evidence are tracked as work proceeds. Planning checks validate parent/child references, inherited prerequisites, criterion coverage, acyclic scheduling, release assignment, and backlog synchronization. Those checks establish plan consistency only. At the time of this decision B001.1 was next; the live ledger is authoritative for the current task.

## Migration impact

Child ledger entries use the existing task fields plus parent_id and parent_criteria. No runtime API, workspace-format, dependency, or release-scope migration is introduced.
