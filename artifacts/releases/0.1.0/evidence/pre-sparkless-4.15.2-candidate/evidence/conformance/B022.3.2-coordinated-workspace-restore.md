# B022.3.2 — Coordinated local workspace snapshot and restore

Date: **2026-10-21**. Result: **passed for the local quiesced workspace profile**.

## Behavior verified

`brickhouse.workspace.snapshot_workspace()` takes an owner lock, rejects active
owners and unfinished persisted job/SQL/Delta operations, checkpoints SQLite
WAL when enabled, and copies the metadata database, managed Delta logs/data,
workspace files, and job history into a new snapshot directory. The manifest
uses the policy `exclude_bytes_preserve_registration`. Registered external
tables remain references; their bytes are not copied, including when an
external location is nested under the source workspace.

`restore_workspace_snapshot()` restores into a new disjoint path, rebases
managed table locations to the restored workspace, and keeps external absolute
locations unchanged. The test restored actual managed rows and Delta history,
the mutation operation journal, succeeded job/run/attempt/output records, and
workspace files. After the external location was moved away, the registration
remained and a table read raised `TableMissingError`.

The safety checks also reject a workspace still held by a service owner, a
queued job after the owner closes, and a snapshot destination that overlaps an
external table location. These checks leave no partial destination behind.

## Limits

This is a full local copy, not an incremental or remote backup service.
Quiescence coordinates BrickHouse writers through the workspace owner lock;
external processes that write SQLite, managed Delta, or external tables are
not coordinated. External table bytes and provider-side state are excluded.
Restoring a workspace that shares external locations with its source does not
make concurrent mutation safe.
