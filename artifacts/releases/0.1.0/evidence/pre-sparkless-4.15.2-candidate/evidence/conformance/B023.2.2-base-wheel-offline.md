# B023.2.2 — Base-wheel offline qualification

Date: **2026-10-21** · Status: **passed for macOS arm64, CPython 3.11.15 and 3.12.13**

## Candidate and environment

The candidate wheel is `brickhouse-0.1.0.dev0-py3-none-any.whl`, SHA-256:

```text
d17b23f20530998c3b5256a4e9ae37101720080e35cc4252c5519330a5ca8979
```

It was installed in two clean environments on macOS 26.5.2 arm64: `/tmp/brickhouse-clean-py311` with CPython 3.11.15 and `/tmp/brickhouse-clean-py312` with CPython 3.12.13. In both, `brickhouse.__file__` resolved to that environment's `site-packages`. The direct runtime dependencies were Sparkless 4.15.0, delta-rs 1.2.1, PyArrow 23.0.1, and SQLGlot 30.24.0. Pytest 9.1.1 and Databricks SDK 0.153.0 were added as test drivers. Both environments passed `uv pip check`, `brickhouse --help`, and `brickhouse --version`. The four optional notebook distributions (`ipykernel`, `jupyter-client`, `nbclient`, and `nbformat`) were absent from both.

Pinned external clients and their local artifacts were provisioned before the offline runs: Databricks CLI 1.21.0, Terraform 1.16.6 with Databricks provider 1.137.0 from a local filesystem mirror, and the separate Databricks SQL connector 4.6.0/kernel 1.1.0 test environment. Terraform used a per-test CLI configuration with checkpoint checks disabled and the pre-provisioned provider mirror; this prevents public registry discovery during `init`. See [HashiCorp's CLI configuration reference](https://developer.hashicorp.com/terraform/cli/config/config-file).

## Offline and process boundary

All G1–G4 pytest groups ran with the candidate wheel imported from `site-packages`, after provisioning dependencies. The runner used macOS `sandbox-exec` to deny outbound networking while permitting TCP loopback and Unix-domain sockets inside that run's unique temporary directory (needed for Terraform's local provider RPC). A Python audit hook rejected non-loopback DNS/connections, `.env` file opens, and Python-launched Java, `spark-submit`, Docker, and full Spark/Delta imports. The candidate environment had no PySpark, delta-spark, or notebook distributions; `JAVA_HOME` and `SPARK_HOME` were removed, and the test `PATH` contained the candidate environment plus `openssl`/`ps` only.

No Databricks credentials were inherited by the test runner, no `.env` file was read, and all observed network traffic was to `127.0.0.1`. SDK/CLI fixtures supplied only synthetic local tokens and loopback hosts inside their isolated test processes. Java, `spark-submit`, Docker, cloud compute, and a real Databricks workspace were not used.
