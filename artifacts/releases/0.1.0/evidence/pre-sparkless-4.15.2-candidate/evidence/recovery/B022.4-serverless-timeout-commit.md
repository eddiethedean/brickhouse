# B022.4 — Serverless timeout and committed Delta recovery

Date: **2026-10-21**. Result: **passed for the selected local serverless worker profile**.

## Behavior verified

The actual `databricks-sdk==0.153.0` Jobs API client used the BrickHouse
loopback server with a synthetic token. A serverless-local Python worker
opened a Sparkless session, appended row `42` to a registered Delta table,
printed its post-commit marker, and slept past its 10-second task timeout. The
run became failed with one `TIMED_OUT` attempt, retained its output, and the
worker process was reaped. Delta still contained rows `0` and `42`, version 1,
and provider history versions 0 and 1. Reopening the workspace retained that
data, the timed-out attempt, and output; no retry or duplicate commit was
created with `max_retries=1` and timeout retry left disabled.

A second serverless-local task intentionally failed before its first Delta
mutation, then retried. The two attempts had distinct IDs and separate output;
the successful attempt appended row `43` exactly once, producing one new
Delta version. Existing classic evidence covers failure retries as distinct
attempts and active worker cancellation after compute restart/termination; the
notebook interruption evidence also checks kernel/descendant cleanup and
committed-data preservation. Together these cover the selected local
serverless and classic recovery cases for B022's fourth criterion.

## Verification

Both new cases passed directly:

```sh
env -u DATABRICKS_TOKEN -u DATABRICKS_HOST \

  tests/unit/test_jobs_api_sdk.py::test_serverless_retry_after_precommit_failure_keeps_attempts_distinct
```

The combined affected local recovery regression suite passed **141 tests**;
Ruff check/format, strict mypy across 70 source files, and `git diff --check`
passed. The classic comparison evidence is [B018.1.2](B018.1.2-job-lifecycle-isolation.md)
and [B017.5](B017.5-notebook-compute-interruption.md).

Environment: Python 3.11.15, SQLite 3.50.4, Sparkless 4.15.0, Databricks SDK
0.153.0 (loopback only), delta-rs 1.2.1, PyArrow 23.0.1, and workspace
metadata schema 20. Databricks credential variables were unset. No personal
workspace, cloud compute, JVM, or Spark driver was used.

## Limits

This evidence qualifies only BrickHouse's mapped local serverless worker
profile. It does not establish Databricks serverless runtime, timeout, retry,
or infrastructure behavior. A timeout after a commit is not automatically
retried; external Python side effects cannot be reconciled by the Delta
journal. The classic restart/termination controls are simulated local resource
metadata around real local worker processes.
