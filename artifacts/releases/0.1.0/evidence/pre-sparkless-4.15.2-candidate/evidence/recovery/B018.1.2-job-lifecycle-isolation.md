# B018.1.2 — Job failure, cancellation, retry, and run isolation

**Status:** passed locally on 2026-10-21  
**Scope:** SDK-backed local worker behavior. All clients targeted the BrickHouse loopback server; no Databricks account or remote compute was used.

## Behavior verified

- When an upstream task fails, its dependent task is persisted as skipped with `UPSTREAM_FAILED`, zero attempts, and no executed side effect. An independent task still runs, and the overall run reports failure.
- A configured retry creates a distinct attempt ID and output record. The failed first attempt and successful second attempt remain separately attributable.
- Restarting or terminating active classic compute cancels the worker, records the canceled outcome, and reaps the worker and its subprocess. A Delta table committed before interruption remains readable.
- Separate SDK runs apply the correct task/run parameter and widget values. Failed-attempt task values do not become visible downstream or leak to later runs.
- A job can read only its granted secret scope. Secret values are redacted from retained worker output and are not written to workspace metadata.
