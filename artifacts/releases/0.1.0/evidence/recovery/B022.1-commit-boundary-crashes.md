## Crash matrix

`tests/unit/test_delta_operation_journal.py::test_killed_writer_reconciles_each_delta_sqlite_boundary` kills the writer at three controlled points, reopens the workspace, and checks the persisted state and actual files:

| Kill point | Restart observation | Replay result |
|---|---|---|
| After SQLite records `COMMITTING`, before calling delta-rs | No `_delta_log` exists; journal retains the operation intent and staged Parquet | Same-payload replay becomes `UNCERTAIN` and does not create a Delta table. Cleanup is rejected while unresolved; changed-payload reuse is rejected. |
| After the native Delta commit, before SQLite finalization | Delta contains the matching transaction and operation metadata; journal is `COMMITTING` | Same-payload replay finds the exact history entry, finalizes version 0, and returns row `42`; changed-payload reuse adds no commit, and owned staging can be cleaned after recovery. |
| After SQLite finalization commits, before the writer returns | Journal is already `COMMITTED` at version 0 and Delta history contains the commit | Same-payload replay returns the recorded version and row `42`; changed-payload reuse adds no commit, and owned staging can be cleaned. |

These cases establish the conservative uncertainty rule before provider dispatch, staged-input retention until reconciliation, and known, idempotent recovery on both sides of SQLite finalization after a Delta commit. They do not establish multi-process/multi-workspace writer serialization, concurrent alias behavior, backup/restore, cross-host coordination, or recovery for arbitrary job side effects.
