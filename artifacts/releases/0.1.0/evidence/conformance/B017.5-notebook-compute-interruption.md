# B017.5 — Notebook SDK profiles and compute interruption

**Date:** 2026-10-21  
**Result:** passed for the selected local notebook profiles  
**Scope:** Phase 0.1 notebook task dispatch and in-flight local kernel cleanup; not Databricks service parity.

## Runtime profile

- BrickHouse `0.1.0.dev0`
- Python `3.11.14` on macOS `26.5.2` arm64
- Sparkless `4.14.1`
- Databricks SDK `0.153.0` (synthetic-token loopback only)
- delta-rs `1.2.1`, PyArrow `23.0.1`
- ipykernel `7.4.0`, jupyter-client `8.10.0`, nbclient `0.11.0`, nbformat `5.11.1`
- Workspace metadata schema `16`

## Results

The pinned Jobs SDK created, submitted, polled, and retrieved output for local `NotebookTask` runs backed by real kernels. All seven compute selections produced actual results from a shared committed Delta table: serverless; classic standard new, existing, and shared; and classic dedicated new, existing, and shared. Shared-compute tasks read the same committed table. Notebook base parameters and run-now overrides were exercised. Notebook environment metadata supplied the environment when the job omitted one; an explicit job environment took precedence.

Marked Python notebook exports ran against that same table under serverless, classic standard, and classic dedicated profiles. Their PEP 723 environment metadata survived conversion to notebook cells.

During active kernel work, compute restart/reset, termination, and timeout each caused the kernel supervisor and spawned descendant to exit. Replacement runs started with fresh kernel state, while a Delta commit made before interruption remained readable. Existing B017.3 coverage also verifies parent-cell cancellation reaps a child notebook kernel and its descendant; see [B017.3 evidence](B017.3-child-notebook-outcomes.md). The schema-upgrade regression preserved an existing queued job/run, allowed a notebook task after migration, and found no foreign-key violations.

## Boundaries

Compute and classic resource lifecycle are simulated local metadata. This evidence covers the selected local profile matrix only; it does not establish Databricks runtime behavior, remote workspace execution, the full Jobs API parameter merge, or notebook-specific task-value/secret parity. Only the tested Python/macOS/arm64 environment is qualified. Notebook environments and dependencies must already be installed. Multi-task `runs/get-output`, remote notebooks, arbitrary source magics, and full Databricks notebook semantics remain unsupported.
