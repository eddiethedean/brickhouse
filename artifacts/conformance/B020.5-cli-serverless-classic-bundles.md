The expanded run covers the new pinned CLI B020.5 workflow, the existing B020.3 bundle workflow, job reset/history, workspace notebook resolution, notebook execution/interruption, migrations, and related Terraform job behavior. Its first attempt exposed a test race where the interruption test read a newly created marker before JSON had been written. The test now writes a temporary marker and atomically replaces the visible file; the final run passed all 60 tests.

The G2 fixture starts with a real local Delta table row `(7, false, "baseline")` and exact `long`, `boolean`, and `string` columns. The serverless bundle validates, deploys, and runs a Python task with mapped environment version 1. The task checks `serverless-local-v1`, consumes bundle parameters through worker widgets, appends order 42 to the registered table, and returns its actual output. The bundle source and parameters are then changed; a second validate/deploy/run appends order 43. The public job ID remains stable across reset/redeploy while two immutable job definitions and two successful run histories remain queryable. `runs/get` returns the stable public job ID, and neither serverless run acquires a classic compute consumer.

The classic bundle validates, deploys, and runs a real `.ipynb` notebook under `classic-standard-local-v1`. It reads the same committed Delta table and verifies all three exact rows and their values. Its run output contains the checked profile and rows. The simulated cluster consumer is released and the resource reaches `TERMINATED` with `is_simulated=true`.

The pinned SDK creates a local Pro SQL warehouse with serverless compute enabled, runs an ordered query over that same table, and checks the actual three-row result and exact SQL result types. Deleting the warehouse makes its local API route return not-found.

Negative cases return explicit errors for `spark_jar_task`, conflicting serverless and classic selectors, and pipelines. They do not create a fourth job. Bundle destroy removes each generated `.bundle/<name>/dev` workspace tree and hides the jobs while preserving the two serverless and one classic run histories.

## Limits

This is a bounded local worker and SQL contract, not Databricks cloud compatibility. Current user identity, SQL warehouse state/allocation, and classic cluster lifecycle are simulated. `serverless-local-v1` maps to a local Python process and is not a Databricks serverless runtime. The CLI requires `disable_auto_optimization: true` for this serverless fixture because automatic optimization retries are unimplemented. Only the tested one-task serverless Python and one-task classic notebook profiles are covered; broad bundle resources, multi-task notebook results, cloud authentication/authorization, remote workspaces, ODBC/JDBC, and cloud compute remain outside this evidence.
