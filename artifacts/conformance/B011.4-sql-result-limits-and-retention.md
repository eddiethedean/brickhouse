# B011.4 — SQL result limits and retention

Date: 2026-10-21

## Local result contract

The local Statement Execution profile accepts only `INLINE` `JSON_ARRAY`.
`row_limit` is bounded to 1–10,000 and `byte_limit` to 1–8 MiB. When either
request value is supplied below the hard default, BrickHouse returns the
largest fitting prefix and sets `manifest.truncated=true`. Without an explicit
smaller request value, results over 10,000 rows or 8 MiB of encoded JSON row
data fail with `RESOURCE_EXHAUSTED`. Unsupported formats and
`EXTERNAL_LINKS` are rejected before statement admission; the route creates no
external URL and performs no filesystem lookup.

Results are persisted in schema 17 as a manifest plus immutable indexed JSON
chunks, each containing at most 1,000 rows. A result may use at most 8 MiB of
persisted manifest and chunk JSON. Results expire 12 hours after completion;
all active result payloads share a 64 MiB workspace budget. On expiry or
capacity pressure, the payload is removed and its row closed. Capacity pressure
closes the earliest-expiring results first. Statement ID, SQL text, terminal
state, and error metadata remain; reads report `CLOSED` and result-chunk fetches
fail explicitly. Schema 16 successful results migrate to indexed chunks and
the same expiry/cap policy during the owner-locked workspace migration.

These are BrickHouse local limits, not Databricks defaults or a remote-parity
claim. The query engine currently returns an Arrow table before this encoder
applies transport limits, so bounded persistence does not claim bounded peak
query memory. No Sparkless Arrow-batch streaming integration is claimed.
