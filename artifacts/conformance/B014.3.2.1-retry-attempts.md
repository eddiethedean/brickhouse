# B014.3.2.1 — Bounded task retry attempts

**Date:** 2026-10-20\
**Status:** complete for the validated local Python retry profile\
**Client:** `databricks-sdk==0.153.0` against local loopback only\
**Metadata:** schema 8; retries append distinct attempt and output records

## Implemented behavior

- Job creation persists the validated task retry policy instead of rejecting it.
- A nonzero observed Python exit retries up to `max_retries`; a worker timeout retries only when `retry_on_timeout=true`. Launch failures, cancellation, and interrupted attempts do not retry.
- `min_retry_interval_millis` delays the next attempt and can be interrupted during shutdown.
- Every retry has a distinct UUID and one-based repository attempt number, observed exit state, and immutable stdout/stderr. The SDK task payload reports the initial attempt as zero and increments it for each retry.
- Dependencies wait for the final outcome after retries. A task that exhausts its retry budget remains failed, so dependents are skipped by B014.3.1.

## Limits

The retry range remains the resolver's bounded 0–10 profile. Automatic task retries do not provide exactly-once side effects. `max_concurrent_runs` above one, global admission limits, restart reconciliation, Spark/Sparkless sessions, Delta effects and worker-facing compute lifecycle are separate or unsupported behavior.
