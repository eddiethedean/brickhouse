# B014.2 — Workspace files and SDK Python execution

**Date:** 2026-10-20\
**Status:** complete for the single-task local Python SDK profile\
**Client:** `databricks-sdk==0.153.0`\
**Metadata:** schema 8; schema 7 upgrades transactionally

## Implemented behavior

- Pinned-SDK multipart `workspace.upload()` creates normalized Python source paths beneath `/Workspace/`; uploads are stored atomically below the owned workspace `files/` directory and capped at 1 MiB.
- The SDK creates a one-task Python script job, rejects missing source files, validates a local compute/environment selector, and submits saved or overridden `python_params` as argv in a fresh child process.
- Idempotency-token replays return the existing run while it is active or terminal. Nonmatching run settings conflict. Credential-shaped parameter values and flags are rejected before persistence.
- `runs/get` reports the observed worker state. `runs/get-output` returns only after the run is no longer queued/running, with stdout in `logs`, stderr in `error`, and truncation metadata.
- Schema 8 stores immutable stdout/stderr for each terminal attempt, capped at 1 MiB per stream. Database triggers reject output mutation/deletion; workspace validation checks schema 8 columns/triggers and permits schema 7 migration.
- Unsupported multi-task jobs, requested task retries, concurrency above one and unsupported run fields return explicit errors.

## Limits

This is a local plain-Python worker flow, not a Databricks runtime emulator. No Spark/Sparkless session, Delta table effect, environment installation, job DAG, automatic retry, cancellation API, process-restart reconciliation, notebook execution or worker-facing compute lifecycle is implemented by this slice. Serverless/classic context values are validation/context only until B014.3/B014.6 and the Sparkless-dependent workload work complete.
