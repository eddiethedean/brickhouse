## Frozen join case

[The fixture](../../tests/fixtures/sql/B019.1.5-join-cases.json) creates two real managed local Delta tables. It includes a null key on each side, one unmatched non-null order, and duplicate `alice` matches. The aliased `INNER JOIN` uses one column-to-column equality and explicit ordering. The exact Arrow result schema and values pass: null does not match null, both `alice` matches remain, and only matched `alice`/`bob` rows appear.

The focused test initially exposed a BrickHouse planner bug: SQLGlot tags an explicit `INNER JOIN` with `kind="INNER"`, while an unqualified `JOIN` omits the kind. The planner had rejected any nonempty kind as unsupported. It now permits the explicit inner kind while continuing to reject outer joins and other non-inner kinds. The regression exercises explicit `INNER JOIN`.

Self-joins, joins with more than one predicate/key, multiple joins, and left outer joins raise `UnsupportedSqlStatementError` with the selected stable messages. No unsupported join returns fabricated rows. No Databricks remote join behavior is claimed.
