## Public Rust contract

- `ExternalCatalogProvider::resolve_table(&str)` returns a validated
  `ExternalTableDescriptor` or a provider miss.
- `ExternalTableDescriptor` records table ID, canonical location, schema, provider,
  format, optional snapshot version, and opaque permissions context.
- `ExternalCatalogProvider::write_table(ExternalTableWriteRequest)` defaults to an
  explicit unsupported error. The request contains the identifier, resolved
  descriptor, `ArrowIpcStream`, save mode, format, ordered options, and partition
  columns. `ExternalTableWriteResult` identifies the unchanged table identity and
  exact committed version.
- `SparkSession::set_external_catalog_provider` installs the resolver on a Rust
  session. Clones share its resolver slot; `new_session()` starts with an empty slot.

The Polars crate tests exercise provider errors, missing/invalid descriptors, local
table and view precedence, typed write delegation, failed writes, external reads, and
new-session isolation. The full `make check-crate CRATE=robin-sparkless-polars` gate
passed at the tested commit, including unit tests, integration binaries, and doctests.

## Isolation boundary and availability

The provider is a synchronous Rust trait. The new hooks are not exposed through the
Sparkless PyO3/Python API, so this revision does not implement or claim Python
callback, GIL, reentrancy, cross-thread, or cancellation isolation. The earlier
B003.3 observation remains in force: `PySparkSession` is unsendable and transferring
it to another Python thread panicked in the tested 4.13.3 probe. BrickHouse must keep
sessions on their owner thread/process until a separately tested binding/ownership
contract exists.

The exact tested source commit is available on the pushed PR branch, but PR #1692 is
open and unmerged and no published Sparkless artifact contains these hooks. Published
4.13.4 remains the only released baseline and cannot be treated as implementing this
API. BrickHouse has not consumed the PR branch as a dependency and makes no integration
compatibility claim. The audit warning and validation command are recorded in
[B009.2](B009.2-sparkless-write-delegation.md).
