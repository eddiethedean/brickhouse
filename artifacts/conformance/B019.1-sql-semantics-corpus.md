## Parent acceptance

The selected projection/filter, aggregate/decimal, date/time, collection, join, DDL/error, and session-profile criteria are implemented and covered by seven required local slices:

1. [Scalar projection, filtering, null handling and coercion](B019.1.1-sql-scalar-cases.md)
2. [Grouped and empty aggregates, decimals and invalid cast](B019.1.2-sql-aggregate-cases.md)

All fixtures are versioned, synthetic, and consumed locally against real Delta files and Sparkless. Exact result types, nulls, errors, ordering rules, and known local mismatches remain visible. The local planner was corrected to accept explicit `INNER JOIN` while preserving typed rejection of unsupported outer/self/multi-key/multiple joins. The session facade now explicitly rejects global temporary views and SQL/DataFrame cache operations for the selected local profiles.

## Mismatches and limits

- Sparkless 4.15.0 returns local COUNT as Arrow `int32` and SUM over `DECIMAL(12,2)` as `decimal128(22,2)`. A bounded Databricks aggregate statement returned `BAD_REQUEST`, so no remote aggregate schema/result was captured.
- Historical 4.15.1 requalification reproduced the timezone-aware Delta timestamp versus naive UTC literal mismatch and filed [follow-up #1720](https://github.com/eddiethedean/robin-sparkless/issues/1720). Sparkless 4.15.2 passes the retained selected predicate case under [PR #1721](https://github.com/eddiethedean/robin-sparkless/pull/1721); SQL projection still returns `timestamp[us]` without source UTC metadata while local values are normalized UTC.
- SQL nested struct field selection (`details.coupon`) now passes with Sparkless 4.15.1 under [upstream PR #1717](https://github.com/eddiethedean/robin-sparkless/pull/1717), which closes [issue #1715](https://github.com/eddiethedean/robin-sparkless/issues/1715). Map constructors and selected array expressions remain explicitly rejected.
- Connect-style deferred analysis and Connect protocol behavior remain unsupported pending B036. Local Sparkless analysis is eager.
- The pre-existing Databricks oracle covers serverless SQL literals and an `Etc/UTC` session only. It does not establish table-predicate, aggregate, nested SQL, classic compute, or serverless Python/notebook parity. No classic cluster was provisioned and no new remote statement was run for B019.1.3–B019.1.7.
- C018 remains `planned`; selected local behavior does not promote broad Spark/Databricks semantic compatibility.
