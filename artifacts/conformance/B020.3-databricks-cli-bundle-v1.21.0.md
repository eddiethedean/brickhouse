# B020.3 — Databricks CLI v1.21.0 local bundle lifecycle

**Date:** 2026-10-20\
**Status:** complete for one classic single-task Python bundle profile\
**Client:** Databricks CLI `v1.21.0`, commit `71934db`\
**Binary:** macOS arm64 release ZIP, SHA-256 `5c899a18bb280a33cb1814418fd1352a6a6e5487a2d9eb850c573114885c2f83`

## Result

The opt-in integration fixture runs the actual CLI against an ephemeral BrickHouse server bound to `127.0.0.1`. The selected `databricks.yml` contains one classic single-task Python job, one `new_cluster` declaration, and a `sync.paths` source directory. The test exercises:

- `bundle validate`, including the synthetic SCIM current-user identity.
- `bundle deploy`, including local directory creation, Python source and JSON deployment-state upload, and Jobs API job creation.
- `bundle run`, which starts a real local Python child process and returns `BUNDLE_LOCAL_OK` and `SIMULATED_COMPUTE=True` in task output.
- Explicit rejection of a notebook task and a pipelines resource.
- `bundle destroy`, which deletes the job through Jobs API 2.2 and removes the managed `.bundle` workspace tree. The job definition and successful run remain in immutable local history after the job is hidden from future API reads.
- Temporary workspace cleanup after the server closes.

The compute record has `is_simulated=True`; no VM or cloud cluster is provisioned. The current-user identity and local API authentication are also simulated. The subprocess receives a synthetic token, an empty temporary CLI config and a temporary home. The local API does not authenticate callers.

The fixture was rerun after metadata schema 12 was added. Its CLI subprocess receives a controlled environment rather than inheriting the test runner's account settings. No `.env`, GitHub secret, personal Databricks account, remote workspace, cloud compute, Spark, or JVM was used.

## Limits

This is a partial local workflow for Databricks CLI v1.21.0. It does not establish CLI authentication or remote Databricks behavior. Only one classic single-task Python bundle is covered. Notebook tasks, pipelines, apps, dashboards, serverless execution, SQL resources, multi-task output, broad bundle syntax, and cloud infrastructure allocation remain unsupported or unverified. Run this integration only when `DATABRICKS_CLI` names the pinned executable; routine CI does not use Databricks credentials.
