# B013.2 — Scoped private worker authentication

Date: **2026-10-20**. Task: **done**. Decision: [ADR 0019](../../docs/decisions/0019-worker-private-authentication.md).

## Behavior

Added a strict version-1 private message envelope and an in-memory `WorkerAuthenticator` to `brickhouse.runtime`. Messages are capped at 64 KiB, use strict UTF-8/JSON with duplicate and unknown fields rejected, and bind request, service, operation, run and attempt IDs. Unsupported protocol versions and invalid payloads fail explicitly.

Each credential uses 256 bits of cryptographic randomness, is scoped to one run/attempt, defaults to a five-minute TTL and cannot exceed one hour. The parent stores only a SHA-256 digest. Missing, malformed, expired, revoked and cross-attempt tokens are rejected. `revoke()` and `revoke_attempt()` close scope; the authenticator is thread-safe.

`run_python_worker(..., credential=...)` verifies the credential's run and attempt match the immutable JSON context before child launch. It places the bearer only in `BRICKHOUSE_WORKER_TOKEN`, never in `BRICKHOUSE_RUN_CONTEXT_JSON`. Credentials are excluded from object repr and `WorkerResult`; the code does not log them or add them to URLs. The parent caller remains responsible for revocation; B013.3 will compose that lifecycle with cancellation/reaping.

The auth and wire primitives are internal. There is no HTTP listener, dispatch route, operation allowlist, job API, or persistence in this slice. The per-attempt bearer is available to user code and its child processes, so this mechanism is not a sandbox. See [06 — Jobs and notebooks](../../docs/plan/06-jobs-notebooks-dbutils.md) and ADR 0019 for route ownership and remaining limits.
