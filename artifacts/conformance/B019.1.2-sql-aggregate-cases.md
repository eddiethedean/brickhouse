# B019.1.2 — Grouped aggregates and decimal results

**Status:** passed locally on 2026-10-21  
**Scope:** grouped COUNT/SUM with null inputs, aggregate behavior over an empty input, decimal widening, and invalid integer cast on the versioned B019.1 orders fixture. The local profile is `spark35-local-v1` with Sparkless 4.15.0.

## Frozen local cases

[The aggregate fixture](../../tests/fixtures/sql/B019.1.2-aggregate-cases.json) reuses the four-row typed orders input from [B019.1.1](../../tests/fixtures/sql/B019.1.1-orders-scalar-query.json). The test writes it to a real local managed Delta table and executes the selected statements through `SqlStatementService` and Sparkless.

For active rows grouped by customer, Sparkless 4.15.0 returns `COUNT(*)` and `COUNT(amount)` as Arrow `int32`, while `SUM(DECIMAL(12,2))` is `decimal128(22,2)`. The two groups are `alice` (2 rows, 2 non-null amounts, total 15.75) and `bob` (1 row, 0 non-null amounts, null total). This keeps null handling and decimal precision/scale visible instead of coercing the result into a presumed Databricks type.

The empty-input aggregate returns one row: count zero and a null decimal sum, with the same `int32`/`decimal128(22,2)` output types. Casting the nonnumeric string `not-a-number` to BIGINT raises Python `ValueError`; the fixture records the stable exception category and message fragment seen from the selected local engine. This case records an invalid-cast outcome; it does not assert a separate ANSI overflow policy.
