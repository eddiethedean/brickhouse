## Verified behavior

The pinned SDK created and fetched simulated serverless (`PRO` plus `enable_serverless_compute=true`), pro (`PRO` with serverless disabled), and classic (`CLASSIC`) warehouse records through the loopback server. The tests exercised paginated list, settings update, stop/start, delete, missing IDs, persistence across workspace reopen, and validation of type/flag combinations, cluster size, auto-stop, and unsupported instance-profile settings.

The workspace compute service persists warehouse identity/settings, lifecycle generations and append-only events, plus durable statement admission leases. It enforces the release policy of one active statement per warehouse, two active statements per workspace, and eight queued statements per warehouse. Release promotes eligible queued statements in FIFO order. Stop and delete invalidate active and queued leases; controlled-clock idle expiry stops an idle warehouse and retains the resulting state after reopen.

## Limits

All represented warehouse allocation and lifecycle are simulated. The local admission bounds and FIFO queue implement BrickHouse's declared release policy; they are not Databricks queue/scaling parity. There is no queue timeout policy, SQL statement REST lifecycle, query execution, connector compatibility, authorization, Photon effect, cloud compute, Databricks account request, Spark, or JVM in this slice. Tests used synthetic SDK credentials, unset Databricks credential variables, and local SQLite workspaces only.
