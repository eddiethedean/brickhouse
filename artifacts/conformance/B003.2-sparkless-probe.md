# B003.2 — Sparkless native bridge feasibility evidence

- Date: 2026-10-16
- Sparkless: 4.13.3, source commit b73067252abd0720ea91ac447bfd3ce027e96a88.
- Python/platform: CPython 3.11.14, macOS arm64.
- Probe dependencies: deltalake 1.2.1, PyArrow 23.0.1; installed into /tmp/brickhouse-b0032-probe only.
- Build command: maturin develop --release from the pinned checkout's python/ directory; compiled the pinned source into the temporary environment. The Sparkless checkout remained unchanged.
- Run command: python artifacts/probes/B003.2-sparkless-delta-bridge.py.
- Result: passed for a small primitive-type subset. A real delta-rs-created Delta table was read by Sparkless; a SQL query bound through a three-part temporary view returned the expected aggregate; a temporary writer adapter materialized native Sparkless rows to a PyArrow table, committed with delta-rs, and both delta-rs and Sparkless read back the committed result.
- Temporary boundary: the adapter is an isolated research probe, not production code. It registers a view per table name and collects the complete Sparkless result to Python before Arrow conversion. There is no streaming/bounded-memory guarantee, no operation journal or authorization context, and no standard Sparkless writer callback into BrickHouse.
- Typed-data failure: a PyArrow decimal128(12,2) input with an explicit Sparkless decimal schema was exposed as struct<amount:double> after ingress. Decimal fidelity therefore fails the 0.1 golden workflow. Nested/timezone values were not tested and are not claimed.
- Path-write failure: DataFrameWriter.format("delta").save(path) returned successfully but produced a regular file without _delta_log; the Delta reader then rejected that path. The current PyO3 save(path) implementation selects Parquet. The separate saveAsTable Delta path still uses Sparkless's local session/catalog implementation.
- No Databricks credentials, host, or remote compute were accessed. The delta-rs writer accepts PyArrow tables under its documented API: [versioned Python writing documentation](https://delta-io.github.io/delta-rs/1.2.1/usage/writing/).

The retained probe is [B003.2-sparkless-delta-bridge.py](../probes/B003.2-sparkless-delta-bridge.py). This demonstrates a possible primitive-only adapter shape, not a release-suitable provider integration. Decimal preservation and a bounded typed callback remain required before phase 0.1 can claim the golden workflow.

## Published release follow-up — 2026-10-19

The exact 4.13.3 regressions documented above were retested against the published Sparkless 4.13.4 wheel. Decimal Delta read, PyArrow Decimal ingress, and Delta path writes all passed their focused local repros; see [B004.2 release verification](B004.2-typed-interoperability.md). The primitive-only bridge remains a research probe: it still collects all rows, does not provide BrickHouse's provider hooks, operation journal, or authorization context, and is not production integration code.
