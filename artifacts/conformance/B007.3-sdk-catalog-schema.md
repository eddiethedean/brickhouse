# B007.3 — SDK catalog and schema workflows

Date: 2026-10-19\
Status: passed local acceptance\
Profile: `databricks-sdk==0.153.0`; BrickHouse `0.1.0.dev0`; Python 3.11.14; SQLite 3.53.4; workspace format 1; metadata schema 3.

## Scope

The test starts BrickHouse's actual loopback HTTP server over a temporary workspace and uses the released pinned Databricks SDK `WorkspaceClient` with explicit host, token, and PAT auth mode. It exercises catalog/schema create, list, get, and delete through the SDK; comment persistence; paginated catalog/schema reads; duplicate and missing errors; invalid names and negative page size; default/system namespace protections; and a conflict when registered table metadata prevents deletion. After server shutdown it reopens the workspace and confirms persisted namespace and table-registration state.

No `.env`, `DATABRICKS_TOKEN`, real account, cloud service, Delta data, or Databricks workspace API was used by this test. The local SDK bearer token is a test literal and is not retained in API logs.

## Implementation profile

- Catalog and schema records are stored in SQLite. Catalog creation creates `default` and `information_schema`.
- Metadata schema 3 adds nullable comments and upgrades existing catalogs by adding `information_schema`. Workspace format remains version 1.
- The server maps duplicate names to `ALREADY_EXISTS` / HTTP 409, missing objects to `RESOURCE_DOES_NOT_EXIST` / HTTP 404, invalid inputs to `INVALID_PARAMETER_VALUE` / HTTP 400, and in-use namespaces to `RESOURCE_IN_USE` / HTTP 409.
- Lists support `max_results` and opaque scoped page tokens. Negative limits and malformed/out-of-scope tokens fail explicitly.
- Only lowercase unquoted identifiers and comments are accepted. Other SDK request fields fail explicitly.
- `information_schema` and the workspace default namespace cannot be deleted. Registered table metadata blocks schema/catalog deletion even when the caller sets `force=true`.

## Limitations

This establishes the tested SDK methods against the local HTTP profile only. It does not establish permission behavior, storage-root or property support, workspace binding, other SDK methods, Databricks API parity, SQL compatibility, Sparkless sessions, or Delta table reads/writes.
