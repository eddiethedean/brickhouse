## Scope

Remove external registrations without touching external files, delete only workspace-owned managed table directories, reject symlink redirection, prevent removal while a write is unfinished, and recover a drop interrupted between physical cleanup and SQLite metadata removal. No Databricks account, `.env`, or cloud storage was accessed.

## Implementation

- External drops remove only the registration and its committed journal rows in a SQLite transaction.
- Managed paths must equal `workspace/tables/<canonical-table-uuid>`. The `tables` root cannot be a symlink.
- On the tested POSIX platform, the service opens the managed root using `O_DIRECTORY | O_NOFOLLOW`, checks the child without following symlinks, and calls symlink-resistant `shutil.rmtree` through that directory file descriptor.
- Managed filesystem cleanup runs before metadata deletion. If recursive deletion fails or the process stops before the SQLite transaction, the table registration remains. A repeated drop finishes cleanup; an already absent directory is accepted.
- Tables with prepared, committing, or uncertain writes cannot be removed. Table operation history is deleted atomically with the registration.

## Limits

The tested filesystem boundary is local macOS POSIX with symlink-resistant `shutil.rmtree`, `O_DIRECTORY`, and `O_NOFOLLOW`. Managed removal fails closed where those safeguards are unavailable. A process interruption can leave a registered table whose managed directory is partly or fully removed until the caller retries drop. The service is not yet wired to SQL, Sparkless, or the HTTP API, and cross-workspace/process coordination is not established.
