**Status:** passed locally on 2026-10-21  
**Scope:** one SDK Python job and three SQL warehouse profiles against the local BrickHouse loopback service. Warehouse profiles and lifecycle states are simulated; no Databricks account or cloud warehouse was used.

## Contract exercised

A pinned-SDK Python job appended an explicitly typed order row to a registered Delta table through the authenticated worker service. The worker's actual output recorded the submitted order/source. The table service confirmed the resulting Delta version 1 and returned the exact versioned schema and rows. A fresh Sparkless session read the same rows.

The SDK then submitted the same ordered SELECT through each local warehouse profile:

- Serverless: `warehouse_type=PRO`, `enable_serverless_compute=true`.
- Pro: `warehouse_type=PRO`, `enable_serverless_compute=false`.
- Classic: `warehouse_type=CLASSIC`, `enable_serverless_compute=false`.

All three statement executions succeeded and returned the same column names/types (`LONG/BIGINT`, `BOOLEAN`, `STRING`) and values as the exact Delta version 1 commit and fresh Sparkless read. The test checked each warehouse's admission lease was released and the table remained at version 1 after each query, then deleted the local warehouse records.
