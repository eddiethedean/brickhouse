Date: 2026-10-19\
Status: passed local acceptance\

## Scope

Implemented `DeltaRsTableService` behind the optional `brickhouse[delta]` extra. The base package still imports without delta-rs or PyArrow and has no mandatory runtime dependencies. The service resolves persistent table handles, reads latest/version/timestamp snapshots, materializes Arrow rows, and writes staged Parquet or Arrow IPC data with create, append, and overwrite modes.

The provider validates canonical registration identity and path stability before access. Staged files must belong to the active workspace and match their recorded byte count, SHA-256, Delta schema, and row count. Writes require exact schema equality and protocol reader/writer 1/2 with no Delta features; partitioned tables, unsupported protocols, and unsupported features fail before row scans. New tables require a missing or empty directory; a nonempty non-Delta external path is preserved and rejected. Delta commit custom metadata carries the operation ID, and the service returns the exact version discovered in commit history. Mutations serialize in-process by both table ID and canonical physical location.

## Limits

No Databricks account or `.env` was accessed. This service is not wired into Sparkless, SQL, the HTTP server, or jobs. The accepted profile excludes partitions, schema evolution, cloud locations, table features, update/delete/merge, and managed-table deletion. Locks coordinate only BrickHouse services in this process. Delta commit metadata is not a durable operation journal; reusing an operation ID can still duplicate data. On an unconfirmed provider result the service raises `UncertainCommitError`; inspect table history before retrying. B008.3 is responsible for persistent fingerprints and restart reconciliation.
