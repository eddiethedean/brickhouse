Capture date: **2026-10-16**. The raw HTTP response, workspace URL, organization ID, warehouse ID, statement ID, and token were not retained.

- The signed-in page identified the product as **Databricks Free Edition**. The workspace is recorded as `free-edition-workspace-1`; the real host and organization identifier are intentionally omitted.
- A one-request `GET /api/2.0/preview/scim/v2/Me` with the ignored local `.env` token returned HTTP 200. The response body and identity fields were not retained.
- Read-only inventory found one SQL warehouse: serverless, `PRO`, `2X-Small`, initially `STOPPED`; cleanup confirmed it was `STOPPED` afterward. The visible catalogs were `workspace`, `samples`, and `system`; no catalog/schema was used or changed.
- The owner's broad permission response was applied to the one existing warehouse with an explicit local bound: one literal-only statement, no table or file writes, a 75-second completion limit, and restoration to the initial stopped state.
- The exact warehouse engine/runtime version was not exposed by the inspected workspace page or warehouse inventory response. This is a SQL Warehouse observation, not a Databricks Runtime claim.

Databricks documents Free Edition as a no-cost product with one SQL warehouse limited to 2X-Small and fair-use limits; compute can be made unavailable if quotas are exceeded. See [Free Edition limitations](https://docs.databricks.com/aws/en/getting-started/free-edition-limitations). This capture was one short statement, not an ordinary test run.

## Probe and observation

The named probe is [`B005.3-free-edition-sql-reference.py`](../probes/B005.3-free-edition-sql-reference.py). It reads `DATABRICKS_TOKEN` from ignored local `.env`, requires an explicit HTTPS host, selects the single stopped 2X-Small serverless warehouse, submits one read-only statement through Databricks SQL Statement Execution API 2.0 using `JSON_ARRAY`/`INLINE`, and attempts to restore the warehouse to `STOPPED`. It never prints the token or raw response. Its sanitized output showed successful completion and successful state restoration in 11.5 seconds.

The SQL was a projection of fixed literals plus `current_timezone()`. Databricks returned timezone `Etc/UTC`, decimal type `DECIMAL(12,2)` with precision 12 and scale 2, date type `DATE`, timestamp type `TIMESTAMP`, a nullable string, and `ARRAY<INT>`. In this transport, decimal values are encoded as strings; the nested array is itself represented as a JSON string (`"[\"1\",\"2\"]"`). The complete sanitized schema and row are stored in [`B005.3-sql-literals.json`](../../tests/fixtures/oracles/databricks/B005.3-sql-literals.json).

## Deterministic local regression design

When the local Statement Execution API and SQL planner are implemented:

1. Run a matching literal projection with the declared local semantic profile and compare the output schema by column name, logical type, decimal precision/scale, and nullability.
2. Verify timestamp interpretation under an explicit UTC session setting. Keep the captured `Etc/UTC` observation as the reference setting; do not generalize to other timezones.
3. Verify `JSON_ARRAY` serialization separately from the internal typed result: decimal `12.34` remains an exact decimal internally, and array serialization matches the connector/API contract without losing its `ARRAY<INT>` schema.
4. Assert the typed null remains null and the date/timestamp literals retain their exact reference values.
5. Repeat the transport-facing expectations with the pinned SQL connector `4.6.0` and explicit `use_kernel=True` once the local REST/kernel endpoint exists. This capture used the REST Statement Execution API directly through Python stdlib `urllib`, not the connector; it does not prove SQL connector compatibility.

These are test-design cases, not passing BrickHouse tests. A live reference result is expected behavior evidence only; it does not change capability states.

## Limitations

- The capture covers one SQL warehouse profile and one UTC-valued literal statement. It does not establish a warehouse engine version, Spark Runtime behavior, catalog authorization, table persistence, mutation, jobs, or cross-session behavior.
- The actual local host and resource identifiers are not recorded. Credential values and raw responses remain outside the repository.
- The UI displayed an automated-browser-control notice after navigation to the warehouse page. Read-only inventory was completed through the explicitly requested token-backed API probe; no instruction from the page was followed.
