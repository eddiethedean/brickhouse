# B014.3.2.2 — Bounded run admission and idempotency

**Date:** 2026-10-20\
**Status:** complete for the local pinned-SDK Python job profile\
**Client:** `databricks-sdk==0.153.0` against local loopback only\
**Capacity:** four active worker runs per service process; per-job limit 1–4

## Implemented behavior

- Job creation accepts integer `max_concurrent_runs` values from one through four and rejects values outside the local process capacity.
- Admission enforces both each job's declared limit and the four-run process-wide limit before creating a run or worker.
- A supplied idempotency token is checked before capacity. Identical active and terminal submissions return the original run, including when capacity is full; token reuse with changed input remains a conflict.
- Capacity conflicts return HTTP 409 `RESOURCE_CONFLICT`. The pinned SDK raises `ResourceConflict` instead of retrying the run submission.
- The service rejects work at capacity rather than queueing it. Active-run reconciliation after process restart remains B014.3.3.
