# B006.1 — Workspace configuration and bootstrap evidence

Date: 2026-10-16

## Result

Implemented and exercised a real filesystem-backed version 1 workspace using Python 3.11.14 and SQLite 3.53.4. The default bootstrap namespace is `main.default`, selected as BrickHouse policy rather than inferred from a personal Databricks workspace. Custom lowercase identifiers are supported through the typed configuration object.

`brickhouse.toml` is strict: it requires exactly the `[workspace]` table and all four version/default settings, rejects unknown keys and invalid identifiers, and refuses config or storage versions this build does not support. `metadata.sqlite` stores the schema migration marker, stable workspace ID, config defaults, and the initial catalog/schema rows. Initialization builds in a sibling staging directory, claims the final path with exclusive directory creation, and refuses a target that appeared after the initial check. Reopen validates the directory layout and metadata using a read-only SQLite URI.

## Scope limits

This is a programmatic bootstrap API and read-only descriptor, not a running workspace service. The slice does not implement owner locks, stale-owner recovery, cross-process isolation, upgrade migrations, writable repositories, CLI lifecycle commands, endpoints, or shutdown behavior; those belong to B006.2/B006.3. It establishes no Databricks client or runtime compatibility claim.
