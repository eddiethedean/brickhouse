# B005.5 — Manual reference-capture workflow

Date: **2026-10-16**.

The optional workflow is [`.github/workflows/databricks-reference.yml`](../../.github/workflows/databricks-reference.yml). It is triggered only by `workflow_dispatch`, requires a `run_probe` boolean acknowledgement, and executes only when the selected ref is `main`. Checkout is pinned to `main` with persisted Git credentials disabled. The capture job has read-only repository permissions, a five-minute timeout, and a repository-wide concurrency group that serializes runs.

The `DATABRICKS_TOKEN` secret is injected only into the curated probe step. The non-secret `DATABRICKS_HOST` repository variable must be configured separately and is restricted to an HTTPS `cloud.databricks.com` workspace host. The workflow invokes only the reviewed B005.3 literal-only probe; that probe requires the existing Free Edition single 2X-Small serverless warehouse to be stopped before execution, submits one statement, limits completion to 75 seconds, and attempts to restore the original stopped state. It does not create catalogs, schemas, tables, or files.

Only the probe's sanitized JSON summary is uploaded, with one-day retention. The token is not available to checkout or upload steps, is not written to a file, and is not printed. There are no push, pull-request, schedule, or other automatic triggers, and normal CI does not depend on this workflow.

## Verification and limits

YAML parsing succeeded for both workflow files, and manual source inspection confirmed the event, branch, secret-scope, concurrency, timeout, curated-script, host-validation, and retention constraints. The workflow was not dispatched from GitHub. The repository secret and `DATABRICKS_HOST` variable were not inspected or changed; the workflow will fail clearly if either is absent. GitHub-side action execution and artifact upload remain unverified.
