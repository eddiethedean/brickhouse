Date: **2026-10-21**. Task: **done**. Parent B021 remains **in progress**.

| `databricks-sql-kernel` | `1.1.0` | SHA-256 `8d7bf7aa002dc2f4864170f1e9185ba10fdf5460efb114269ec9337b084bd501` (B045 verified wheel) |

The real connector was invoked with `use_kernel=True`, telemetry disabled, an 8-second socket timeout and one retry attempt. As established in B045, its pinned kernel path uses the host string (including the ephemeral port) and the contained `_tls_trusted_ca_file` option; the connector port setting is not forwarded by this version.

## BrickHouse loopback result

`tests/integration/test_databricks_sql_kernel_b0211.py` created a temporary BrickHouse workspace and a local, serverless-enabled simulated SQL warehouse. It served the actual diagnostic API over an ephemeral loopback HTTPS listener. An ephemeral CA signed a certificate with an IP subject alternative name for `127.0.0.1`; the client verified both the CA and host name. The client process received only an explicit loopback host/path, that local CA, and a synthetic bearer credential. `DATABRICKS_TOKEN` and `DATABRICKS_HOST` were absent.

The pinned kernel made exactly one request:

```json
{
  "method": "POST",
  "path": "/api/2.0/sql/sessions",
  "authorization_present": true,
  "authorization_scheme": "Bearer",
  "authorization_matches_synthetic": true,
  "body_keys": ["execution_mode", "warehouse_id"],
  "execution_mode": "FAST",
  "warehouse_id": "<local simulated warehouse ID>"
}
```

The request reached BrickHouse and its warehouse identity resolved. BrickHouse returned HTTP 501 `UNSUPPORTED_OPERATION` with `warehouse identity is valid; connector session lifecycle is not implemented`. The released connector surfaced the response as `DatabaseError` with `HTTP 501: ...`. No session was created, no statement request followed, and no SQL rows were returned. This is a successful strict-TLS/auth transport proof and a concrete session-interoperability limit; it is not connector SQL compatibility.

Because session open stopped the client before query dispatch in the original B021.1 run, that slice did not exercise statement parameters, schema/fetch batches, metadata methods, cancellation or result lifetime. Those remain B021.2 work. Default Thrift remains a distinct untested profile.

## Reproduction

```bash
env -u DATABRICKS_TOKEN -u DATABRICKS_HOST \
  BRICKHOUSE_SQL_CONNECTOR_PYTHON=/path/to/isolated/bin/python \
  .venv/bin/pytest -q --tb=short \
  tests/integration/test_databricks_sql_kernel_b0211.py
```

The original B021.1 run passed locally (**1 passed**) and observed the HTTP 501 described above. The integration has since been extended to verify the actual connector's successful session-open/close lifecycle; its current behavior is in [B021.2.1](B021.2.1-sql-kernel-session-lifecycle.md). Normal CI skips this integration unless `BRICKHOUSE_SQL_CONNECTOR_PYTHON` is explicitly set. It never loads `.env`, reads the real account token, calls a Databricks host, or allocates cloud compute. The pinned wheels, capture mechanics and original transport constraints are detailed in [B045](B045-sql-connector-loopback.md).
