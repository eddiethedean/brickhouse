# B004.2 — Delta typed interoperability probe

## Environment and fixture

- Date: 2026-10-19
- Published Sparkless Python wheel: `sparkless==4.13.4`, `cp38-abi3-macosx_11_0_arm64`
- Wheel SHA-256: `ef948dd5a2809621d41fbf1313bbe3db618ebfbe4fe26817151a02cf612e7828`
- Upstream release: [`v4.13.4`](https://github.com/eddiethedean/robin-sparkless/releases/tag/v4.13.4), commit `34049bde128931e21bf34b761cfa10007d62af5e`
- Python: CPython 3.11.14, macOS arm64
- Python Delta writer: `deltalake==1.2.1`
- PyArrow: `23.0.1`
- Probe: [B004.2-typed-interoperability.py](../probes/B004.2-typed-interoperability.py)
- The probe wrote only synthetic Delta files under temporary local directories. It made no Databricks calls and used no account credentials.

## Verification

Installed the published wheel into a fresh isolated environment and ran:

```text
/tmp/brickhouse-sparkless-4134/bin/python -u artifacts/probes/B004.2-typed-interoperability.py
```

Result: **passed**. A delta-rs-created table was read through Sparkless with exact `decimal(12,2)`, nullable values, bigint, date, UTC-valued timestamp, string, boolean, array, and nested struct types/values. A Sparkless SQL projection over that table preserved the decimal schema and exact `Decimal("10.50")` value. PyArrow decimal ingress produced the same decimal schema and exact values. The SQL path returned rows `(1, Decimal("10.50"))` and `(2, None)`.

The same probe verified the old Delta path-writer regression: `.format("delta").mode("overwrite").save(path)` created a directory containing `_delta_log`, Delta version 0, and rows that Sparkless could read back.

## Upstream blocker follow-up

The previously reproduced 4.13.3 issues now pass their named local cases with the published 4.13.4 wheel:

- [#1683 — PyArrow Decimal ingress](https://github.com/eddiethedean/robin-sparkless/issues/1683): `decimal(12,2)` schema, exact value, and null were preserved.
- [#1686 — Decimal Delta read panic](https://github.com/eddiethedean/robin-sparkless/issues/1686): cross-reading the real Delta snapshot returned a DataFrame and exact Decimal values without a panic.
- [#1684 — Delta format path writer](https://github.com/eddiethedean/robin-sparkless/issues/1684): the path writer committed a readable Delta table instead of a plain Parquet file.

This resolves those three observed regressions for the tested release and cases. It does not establish a broad Sparkless compatibility envelope, non-UTC timestamp conversion, other decimal precision/scale or overflow cases, all nested types, Delta protocol feature support, BrickHouse writer delegation, or production recovery. B004.3 separately selected `deltalake==1.2.1` and tested transaction recovery on a default-protocol local table; see [B004.3](B004.3-transaction-recovery.md).
