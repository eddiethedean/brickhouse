# B015.1.1 worker-scoped PySpark imports

Date: 2026-10-21

## Scope

The managed child worker lazily provides `pyspark`, `pyspark.sql`,
`pyspark.sql.functions`, `pyspark.sql.types`, and `pyspark.sql.window` from the
published Sparkless 4.14.1 public Python modules. Imports are installed only in
the worker process. A conflicting `pyspark` package on the worker import path,
preloaded PySpark modules, and unsupported namespaces such as `pyspark.rdd`,
`pyspark.ml`, and `pyspark.java_gateway` fail with named BrickHouse import errors.
The worker launcher also preserves a virtual environment's Python symlink so the
child process runs under the configured interpreter environment.

## Local checks

Command:

```text
env -u DATABRICKS_TOKEN -u DATABRICKS_HOST PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTHONPATH=src /tmp/brickhouse-plan-audit/bin/python -m pytest -q tests/unit/test_worker_imports.py tests/unit/test_worker.py
```

Result: **16 tests passed**. Actual job scripts imported each selected namespace
inside two fresh child workers. Tests confirmed the exported objects are the
published Sparkless objects, module state set by one worker is absent in the
next worker, the parent interpreter's `sys.modules` is unchanged, unsupported
namespaces fail explicitly, and a conflicting package is rejected before its
initializer executes. The existing worker tests also verified that the child
uses the selected virtual environment prefix.

Ruff check and format passed for the changed source and tests. Strict mypy passed
for `worker.py`, `worker_entry.py`, and `worker_imports.py`. `DATABRICKS_TOKEN`
and `DATABRICKS_HOST` were unset; no Databricks account or remote compute was used.

## Limits

This slice establishes import compatibility only. It does not create or configure
the job's Sparkless session, bind effective serverless/classic settings, expose
registered tables to worker reads, or claim Spark Connect behavior. Those are
covered by B015.1.2 and B015.1.3.
