Date: 2026-10-21

- [B019.2.1 — SQL UPDATE/DELETE](B019.2.1-sql-update-delete.md): journaled native delta-rs mutation, exact provider metrics, no-op/failure/replay handling, and Sparkless-visible state.

Together, the four slices prove the B019.2 acceptance path: SQL mutations use the shared table service and declared provider; history comes from committed Delta records; and time travel uses the same versioned table identity/snapshot contract. The combined focused SQL, provider, Sparkless adapter, worker-session, and worker regression suite passed **128 tests** with Sparkless 4.15.0 and delta-rs 1.2.1. Databricks credential variables were unset; no real workspace or cloud compute was used.

## Limits

These results establish only the selected local SQL/provider envelopes. They do not establish general Spark/Databricks SQL parity, external-host concurrency, or non-integer time-travel selectors. C018 remains planned.
