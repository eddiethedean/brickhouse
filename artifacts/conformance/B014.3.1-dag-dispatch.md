# B014.3.1 — Sequential DAG dispatch and dependency failure propagation

**Date:** 2026-10-20\
**Status:** complete for sequential local Python-script DAGs\
**Client:** `databricks-sdk==0.153.0` against local loopback only\
**Metadata:** schema 8; no schema change

## Implemented behavior

- SDK job creation accepts up to ten validated Python script tasks, retaining task parameters, dependencies and immutable resolved context.
- The service uses a stable topological order and starts at most one task worker at a time. The repository checks dependency success again inside the transaction that creates an attempt.
- Failed, cancelled, skipped or interrupted dependencies persist a `SKIPPED` task with zero attempts. The SDK task state reports `UPSTREAM_FAILED` or `UPSTREAM_CANCELED` for those outcomes.
- Independent tasks continue after a task fails. A failed job run is finalized only after remaining eligible tasks and dependency skips have truthful terminal states.
- The SDK run-now `python_params` override remains limited to single-task jobs. Multi-task output retrieval is explicitly unsupported by this pinned route.

## Limits

This sequential local dispatcher supports only Python scripts and default `ALL_SUCCESS` dependencies. It does not implement retries, concurrency above one, process-restart reconciliation, task cancellation requests, worker-facing compute lifetimes, Spark/Sparkless sessions, Delta effects, or multi-task `get_run_output`. No Databricks account, `.env`, cloud compute, Spark, or JVM was used.
