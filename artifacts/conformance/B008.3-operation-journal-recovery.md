## Scope

Persist operation IDs, fingerprints, transaction versions, and exact commit versions for local Delta writes. Reconcile a provider commit after process death, reject changed-payload key reuse, and retain uncertainty when the commit cannot be confirmed. Routine tests use local files and SQLite only; this slice did not read `.env`, access Databricks, or use a cloud workspace.

## Implementation

- Metadata schema 4 creates `table_operation_journal` with a foreign key to the registered table and uniqueness scoped to `(table_id, operation_id)` and `(table_id, transaction_version)`.
- The journal persists intent, input/options/schema fingerprints, base version, row count, and monotonic per-table application transaction version before provider dispatch.
- Delta writes include the registered table ID and transaction version as the provider application transaction, plus the operation ID and payload fingerprint in commit metadata.
- A successful or replayed write returns a commit version only after the journal and provider history agree. Replays search the latest 100 Delta history entries.
- Provider outcome failures and failed reconciliation preserve an uncertain state. Unfinished operations block other writes; same-payload replay can attempt reconciliation. Changed-payload reuse raises an explicit error.

## Limits

The tested guarantees cover the single-workspace local SQLite and delta-rs profile. Delta history reconciliation checks only the latest 100 entries. If transaction metadata or the exact history row is missing or expires, the service remains uncertain and blocks automatic retries. This does not establish cross-workspace or cross-host coordination, startup-wide automatic reconciliation, cloud object storage, or recovery for arbitrary job side effects. The service remains separate from SQL and Sparkless routing.
