The actual connector opened a session over verified loopback HTTPS and closed it. Sanitized request shapes:

```json
{
  "method": "POST",
  "path": "/api/2.0/sql/sessions",
```

```json
{
  "method": "DELETE",
  "path": "/api/2.0/sql/sessions/<session-id>?warehouse_id=<local warehouse id>",
  "body_keys": [],
  "authorization_scheme": "Bearer",
  "authorization_matches_synthetic": true,
  "response_status": 200

```

The session DELETE query string is required by the pinned kernel even though the documented Python model describes the warehouse ID in a request object. BrickHouse accepts that observed form, checks it against the live session, and does not require a body.

## BrickHouse contract and limits

Sessions are ephemeral and scoped to one diagnostic server. Each receives a random UUID-hex ID and immutable warehouse, catalog, schema, execution mode, and configuration state. Warehouse and namespace resolution happens before returning the ID. Unknown IDs return 404, a mismatched warehouse returns 400, missing warehouses return 404, stopped warehouses return 409, and repeat close returns 404. Non-empty per-session SQL configuration receives 501 `UNSUPPORTED_OPERATION`; BrickHouse does not claim settings are applied when query execution cannot consume them.

The direct API regression opened independent `main.default` and `analytics.dashboards` sessions and verified their contexts remained distinct. It also exercised unsupported session configuration, missing/stopped warehouse, cross-warehouse close, close and repeat-close. The actual connector integration verified its session-open and bodyless session-close requests over strict TLS with a trusted ephemeral CA and a synthetic bearer value. Real Databricks credentials were absent from its child environment.

This slice adds real session creation/close behavior only. It does not submit a SQL statement, associate result IDs with sessions, implement session configuration, or establish query/result compatibility. B021.2.2 covers connector execution, parameters and fetching; C031 remains partial and Thrift remains separate and untested.

**Historical scope note:** those limits describe the B021.2.1 completion. The shared opt-in integration was extended in B021.2.2 to add a separate SEA-mode parameterized query/result case and statement close while retaining the kernel create/close case; see [B021.2.2 evidence](B021.2.2-sql-connector-inline-results.md).
