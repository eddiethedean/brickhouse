# B019.2.3 — SQL DESCRIBE TABLE and DESCRIBE HISTORY

Date: 2026-10-21  
Result: **passed locally** for registered Delta schema inspection and the selected committed-history result profile.

## Implemented behavior

`DESCRIBE TABLE` binds a registered table, opens and validates its current Delta snapshot through `DeltaRsTableService`, and emits the top-level fields in Delta schema order. Its exact Arrow output schema is `col_name: string not null`, `data_type: string not null`, `comment: string nullable`. Primitive, decimal, array, map, and struct schema types render as selected Spark SQL type text. A comment is returned only when present in the schema metadata.

`DESCRIBE HISTORY` reads the public delta-rs `DeltaTable.history(limit=100)` result through `DeltaRsTableService`. The exact Arrow output schema is `version: int64 not null`, `timestamp: timestamp[ms, tz=UTC] not null`, `operation: string not null`, `operationParameters: map<string,string> nullable`, `readVersion: int64 nullable`, `operationMetrics: map<string,string> nullable`, and `engineInfo: string nullable`. Results preserve the provider's newest-first commit order. Numeric provider parameter/metric values are represented as strings. Absent provider values remain null; SQL does not synthesize identity, job, notebook, cluster, isolation, or other unavailable Databricks fields from BrickHouse metadata.

The unsupported DESCRIBE EXTENDED/DETAIL variants and DESCRIBE HISTORY LIMIT syntax reject explicitly. History is bounded to the latest 100 provider records. There is no direct log-file parsing or operation-journal reconstruction.

## Limits

The local result schema is a bounded provider contract, not proof of full Databricks `DESCRIBE`/`DESCRIBE HISTORY` parity. History supports only the most recent 100 entries and omits metadata not exposed by the selected delta-rs records. Extended/detail descriptions and caller-selected history limits remain unsupported. VERSION AS OF remains B019.2.4; C018 remains planned.
