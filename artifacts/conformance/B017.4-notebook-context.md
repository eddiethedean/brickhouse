# B017.4 — Notebook compute profiles, environments, and reset

Date: 2026-10-21  
Environment: Python 3.11.14, macOS 26.5.2 arm64, Sparkless 4.14.1, ipykernel 7.4.0, jupyter-client 8.10.0, nbclient 0.11.0, nbformat 5.11.1

## Implemented contract

The optional notebook runner accepts both the nested resolved profile input used by local callers and the flattened immutable worker context emitted by the job runtime. It validates the selected Sparkless profile and environment before starting an execution kernel or writing an artifact.

Serverless execution requires `serverless-local-v1`, environment version `1`, and an environment name matching the selected interpreter (`serverless-python311-local-v1` in this run). The selected interpreter must already have the pinned `ipykernel==7.4.0` and `sparkless==4.14.1`; declared environment dependencies must be exact pins already installed in that interpreter. The test environment verified `deltalake==1.2.1` and `pyarrow==23.0.1`. The runner inspects metadata with the selected interpreter and never installs packages.

Classic standard and dedicated contexts require the `spark35-local-v1` runtime alias, matching access mode, and explicit ANSI/timezone settings. They do not accept serverless environment metadata. All profiles apply the resolved settings over the shared local session defaults. Unsupported settings, mismatched environments, missing packages, and incompatible profile fields fail before the notebook kernel starts.

Each invocation creates a fresh kernel and profile-bound Sparkless session. Values persist across cells in that kernel; a later invocation has no previous Python variables or session-setting overrides. Invocation parameters override tagged notebook parameter-cell defaults. Resolved worker widget parameters override notebook widget defaults. The flattened worker context preserves optional classic compute identity, generation, state, and simulation fields for the later notebook supervision/cancellation work.

This follows Databricks' documented [job parameter pushdown and precedence](https://docs.databricks.com/aws/en/jobs/job-parameters) and [notebook task base/run-now parameter behavior](https://docs.databricks.com/aws/en/reference/jobs-2.0-api), within the local contracts above. No SDK notebook task dispatch or actual Databricks job parameter merge is claimed.

## Limits

This is a local execution profile, not Databricks compute or environment provisioning. The runner verifies an already provisioned interpreter; it does not create or update environments. Full job-level parameter resolution, notebook SDK task dispatch, a live compute attachment monitor, child notebook invocation, cancellation during a cell, and descendant cleanup remain outside this slice. Those execution and cancellation paths belong to B017.3/B017.5 and B018.2. The compute IDs used by classic contexts are simulated metadata from the local service.
