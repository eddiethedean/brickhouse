# B019.2.4 — SQL VERSION AS OF snapshots

Date: 2026-10-21  
Result: **passed locally** for non-negative integer Delta version selectors.

## Environment

- Python 3.11.14
- Sparkless 4.15.0
- `deltalake==1.2.1`
- PyArrow 23.0.1
- SQLGlot 30.24.0
- Databricks SDK 0.153.0
- SQLite 3.53.4; workspace metadata schema 19

## Implemented behavior

The SQL planner accepts a literal, non-negative integer `VERSION AS OF` selector on registered tables. It binds the exact table identity and selected version, removes the clause from the SQL passed to Sparkless, and opens a fresh Sparkless session whose external-catalog descriptor is pinned to that Delta version. The selected snapshot is also read through `DeltaRsTableService.read_table(SnapshotSelector(...))` before execution, so unavailable snapshot files raise a typed error before Sparkless dispatch. There is no latest-version retry or silent fallback. Historical-snapshot Sparkless sessions are read-only.

Successful SQL results preserve the historical provider Arrow schema and rows. They match both direct `DeltaRsTableService` reads and direct Sparkless reads pinned to the same table ID/version. A future version raises `SnapshotUnavailableError`. After a public Delta vacuum removes the files for a historical version, the corresponding SQL read also raises `SnapshotUnavailableError`, while an ordinary latest read still returns the current rows.

Timestamp selectors, negative, decimal, and string version values, and version ranges are not part of this profile. They reject as typed planner/parse errors. Version selectors are integer literals; caller parameters and time travel outside SELECT/CTAS-bound SELECT queries are not qualified by this slice.

## Evidence

- `tests/unit/test_sql_time_travel.py::test_sql_version_as_of_reads_one_pinned_snapshot_through_sparkless`: exact version-0 schema and rows match SQL, direct service, and direct Sparkless reads, while latest SQL sees the later append.
- `tests/unit/test_sql_time_travel.py::test_unsupported_snapshot_selectors_reject_during_planning`: timestamp, negative, decimal, string, and malformed range selectors reject; a current-version query remains unchanged.
- `tests/unit/test_sql_time_travel.py::test_future_version_as_of_raises_without_falling_back_to_latest`: future version is typed unavailable and latest data is not substituted.
- `tests/unit/test_sql_time_travel.py::test_expired_snapshot_raises_without_falling_back_to_latest`: public Delta vacuum removes the old data file, the requested version fails as unavailable, and latest reads still return the current row.
- Combined focused SQL, provider, Sparkless adapter, worker-session, and worker regression suite: **128 passed**.

The suite ran with `DATABRICKS_TOKEN`, `DATABRICKS_HOST`, and `DATABRICKS_PROFILE` unset. It used local Delta files and Sparkless 4.15.0; no Databricks workspace, cloud compute, or JVM was used.

## Limits

This qualifies only the selected local literal integer `VERSION AS OF` route and retained-file behavior for delta-rs 1.2.1. Timestamp time travel, parameterized selectors, broader SQL snapshot syntax, remote Databricks behavior, and cross-process concurrent vacuum/write behavior remain unqualified. C018 remains planned.
