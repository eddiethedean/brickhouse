# B017.1 — Parameterized ipynb kernel conformance

Date: 2026-10-21

## Selected behavior

`brickhouse.notebooks.execute_ipynb()` executes a valid Python `.ipynb` in a new,
explicitly selected IPython interpreter. It creates a per-run kernel specification
and isolated Jupyter/IPython directories, passes only the bounded worker context
and minimal worker environment, and always shuts down the kernel it created.
Caller parameters must be finite JSON with valid non-reserved Python identifiers;
they are injected after a single code cell tagged `parameters`, or before the first
user cell when none is tagged. The worker bootstrap creates the profile-bound
Sparkless session and local `dbutils` object inside the kernel namespace.

Successful execution writes an atomic `.ipynb` output artifact with cell outputs
and counts user code cells. A cell error is saved into the artifact and raised to
the caller as `NotebookExecutionError`, which identifies the artifact and error
type. Source notebooks are never overwritten.

## Conformance evidence

The test environment was installed from `requirements/dev.txt` with hash checking
in `/tmp/brickhouse-b0171-env`. It used Python 3.11.14, BrickHouse 0.1.0.dev0,
Sparkless 4.14.1, ipykernel 7.4.0, jupyter-client 8.10.0, nbclient 0.11.0, and
nbformat 5.11.1. `pip check` found no broken requirements.

The five real-kernel tests in
[`tests/unit/test_notebook_runner.py`](../../tests/unit/test_notebook_runner.py)
verified:

- tagged-cell defaults and JSON parameter overrides;
- Spark DataFrame execution and worker-local widget, DBFS mkdirs/put/head;
- stream and IPython display outputs in the saved notebook artifact;
- distinct fresh kernels and no state leakage between invocations;
- absence of a parent-process `DATABRICKS_TOKEN` sentinel in the kernel;
- saved cell error outputs and propagated `NotebookExecutionError`; and
- rejection of a non-mapping parameter value before kernel creation.

## Limits

This is an execution primitive, not SDK job/notebook dispatch. It accepts Python
`.ipynb` only; source exports, magics, `%run`, child notebook return values,
notebook task values/secrets, notebook-specific widget/parameter precedence,
external compute attachment/reset, cancellation, and descendant cleanup remain
with later B017 children. `dbutils` secrets are not loaded into this kernel.
Notebook code is trusted local Python and is not sandboxed; output size is not
bounded by this slice. The passing local profile is not evidence of Databricks
runtime parity.
