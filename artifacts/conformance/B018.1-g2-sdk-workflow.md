## Contract exercised

The G2 workflow submits real Python worker processes through the pinned Databricks SDK. A producer receives task parameters and scoped widgets, reads a job-granted synthetic secret, appends explicitly typed rows through the attempt-authenticated parent Delta service, and publishes task values. A declared dependent worker reads the task value and same committed rows. Actual per-task output, data/schema, and Delta versions are compared with fresh Sparkless-session and SQL Statement Execution reads.

Focused lifecycle coverage verifies dependency failure and skip behavior, independent task progress, distinct retry attempts, compute-interruption cancellation and descendant reaping, preservation of earlier commits, and parameter/widget/secret/task-value isolation. The data-flow is exercised through all seven selected serverless/classic-standard/classic-dedicated job compute selectors with truthful simulated resource lifetimes. A job-produced commit is read through serverless, pro, and classic local SQL warehouse profiles.
