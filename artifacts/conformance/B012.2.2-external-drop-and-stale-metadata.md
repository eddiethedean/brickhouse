# B012.2.2 — External drop and stale metadata

Date: 2026-10-21

## Result

Passed local ownership and invalidation checks for external registrations and an existing Sparkless session.

- Dropping an external registration removes its catalog metadata while preserving the external directory and its sentinel bytes.
- A `TableHandle` captured before the drop can no longer read or append after registration removal; both operations fail with `TableMissingError` before touching the external location.
- An already-open Sparkless session reads a registered managed table, then observes its removal. A subsequent lookup fails with the public `SparklessError`, and a subsequent `saveAsTable()` append fails with `UnregisteredTableWriteError`. The removed managed directory remains absent.
- This verifies re-resolution through the same active session and service handle. It does not claim revocation of a DataFrame that was already resolved before the registration was dropped.
