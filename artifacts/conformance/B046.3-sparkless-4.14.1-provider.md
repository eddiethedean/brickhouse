# B046.3 — Published Sparkless 4.14.1 provider verification

Date: **2026-10-20** (America/New_York). Result: **passed for the selected local provider envelope**. Sparkless 4.14.1 fixes the nullable-struct cases that blocked the 4.14.0 probe. The 4.14.0 report and raw output remain historical evidence.

- The public registration signature is `SparkSession.set_external_catalog_provider(self, provider)`. Only the macOS arm64/Python 3.11 wheel was installed and exercised here. Other wheel platforms remain unqualified by this report.

## Probe results

Both commands ran against synthetic local Delta files with Databricks credential variables removed. They do not load `.env`, contact the owner's workspace, start Spark/JVM, or fabricate commit receipts.

env -u DATABRICKS_TOKEN -u DATABRICKS_HOST /tmp/brickhouse-plan-audit/bin/python -u artifacts/probes/B046.3-published-python-provider.py --output artifacts/conformance/B046.3-sparkless-4.14.1-provider.json
env -u DATABRICKS_TOKEN -u DATABRICKS_HOST /tmp/brickhouse-plan-audit/bin/python artifacts/probes/B046.3-null-struct-repro.py --output artifacts/conformance/B046.3-null-struct-repro-4.14.1.json

The first probe passed **14/14** selected real Delta provider checks: DataFrame/reader/SQL/catalog reads; journaled Decimal, scalar-null, array and struct append; SQL `INSERT SELECT`; overwrite and exact commit versions; version-pinned reads; provider isolation for fresh sessions; explicit callback/lookup/write-setting failures without mutation or local fallback; provider detach; workspace reopen; independent owner threads; and child-process termination before and after commit.

The second probe passed **6/6** null-struct contracts. Python row and Arrow ingestion preserve a null parent struct separately from a valid struct with a null field through both `collect()` and provider IPC. Native Delta reads preserve the same distinction through both paths. This closes the exact regressions tracked by [#1694](https://github.com/eddiethedean/robin-sparkless/issues/1694) and [#1695](https://github.com/eddiethedean/robin-sparkless/issues/1695), which were fixed by [PR #1696](https://github.com/eddiethedean/robin-sparkless/pull/1696) and [PR #1697](https://github.com/eddiethedean/robin-sparkless/pull/1697).

The machine-readable observations are [the 14-case provider report](B046.3-sparkless-4.14.1-provider.json) and [the six-case nullable-struct report](B046.3-null-struct-repro-4.14.1.json). Existing 4.14.0 reports retain the failures observed on that older release.

## Limits and disposition

Inputs were small synthetic local fixtures. The Sparkless writer buffers an entire Arrow IPC stream before the Python callback; callback limits do not bound that earlier materialization. Native sessions must stay on their creating thread. Provider callbacks are synchronous, do not accept an in-process cancellation token, and wrap arbitrary Python exception types. These remain adapter and worker-containment constraints.

This verifies a published upstream hook and clears the B046.3 artifact/type blocker. It is not itself a BrickHouse production adapter or a Databricks behavior claim. B010 implements the adapter in slices; B023 still must qualify publicly available artifacts on every platform BrickHouse advertises.
