## Implemented contract

`brickhouse.notebooks.execute_databricks_python_source()` accepts a UTF-8 `.py` source export with the Databricks header on its first line. It parses `# COMMAND ----------` separators and `# MAGIC` comments as structure, then uses explicit Python, SQL, Markdown, and inline `%run` handlers. SQL uses the injected Sparkless session and exposes the latest result as `_sqldf`. `%run` executes a marked relative `.py` source-export notebook in the caller's kernel namespace, so its definitions are available to later caller cells. Nested targets are checked before kernel startup; missing paths, escapes, cycles, unsupported suffixes, or unmarked files fail explicitly. The source file is not modified; execution output is saved as an `.ipynb` artifact.

The implemented source marker and cell boundary follow the [Databricks source import/export format](https://docs.databricks.com/aws/en/notebooks/notebook-export-import?language=SQL). The supported magic set is an intentional local subset of the [documented notebook commands](https://docs.databricks.com/aws/en/notebooks/notebooks-code). `%run` follows the documented inline execution behavior; `dbutils.notebook.run()` remains a separate child-run contract ([Databricks notebook workflows](https://docs.databricks.com/aws/en/notebooks/notebook-workflows)).

## Limits

This is not full Databricks notebook parity. Only marked local Python `.py` exports and relative in-tree `%run` targets are supported; absolute workspace resolution, other source languages, source-export environment manifests, serverless/classic mode corpus, SDK job dispatch, child `dbutils.notebook.run/exit`, widget/parameter precedence, notebook task values/secrets, cancellation, compute attachment/reset, and kernel descendant-interruption behavior remain open in later B017 children. Unsupported language, shell, file-system, package-install, and unknown magics are rejected. SQL behavior is the selected local Sparkless subset, and SQL result display currently collects rows into the output artifact.

No new Sparkless upstream feature gap surfaced in this slice. Existing reported gaps remain tracked separately, including [robin-sparkless #1707](https://github.com/eddiethedean/robin-sparkless/issues/1707).
