## Predetermined routing

| Operation | Selected local route |
|---|---|
| SELECT | Planner binds source names to the authoritative registered table IDs; `SqlStatementService` opens an isolated `SparklessSessionFactory` session over those provider descriptors. |
| CREATE TABLE AS SELECT | Evaluate the SELECT in Sparkless; after success, register the table and commit through `DeltaRsTableService`. An execution failure propagates before table registration. |
| CREATE/DROP SCHEMA | `CatalogService` and the workspace catalog repository. |
| CREATE/DROP TABLE | Shared catalog/table registration and `DeltaRsTableService`; physical managed data remains the registered Delta table. |
| UPDATE/DELETE/MERGE | Journaled `DeltaRsTableService` operations through delta-rs 1.2.1. Only the selected B019.2 predicates and single-key MERGE clauses are qualified. |
| DESCRIBE TABLE/HISTORY | Current registered Delta schema or the public provider history API, bounded to the newest 100 commits. |
| VERSION AS OF | Validate/read the selected Delta snapshot first, then use a table-ID/version-pinned Sparkless descriptor. Only non-negative integer literals are supported; historical sessions are read-only. |

The table above describes actual dispatch in `SqlStatementService.execute`, its planned-query helper, and the shared catalog/table services. The same registered table ID and Delta location are visible to Sparkless DataFrames, SQL and workers; there is no separate managed-table copy. The base dependency set pins Sparkless 4.15.0 and does not include DuckDB. No DuckDB executor is enabled. A future executor must be selected in the plan before dispatch for an evidenced profile and must use the shared registered table authority. Exceptions do not trigger another executor.

## Qualified types and boundaries

The selected B019.1 fixtures cover null, boolean, integer, floating-point, string, decimal(12,2), DATE, UTC TIMESTAMP, nullable array and nullable struct values. Tested SQL families include scalar projection/filter/null/coercion, grouped COUNT/SUM, selected date/time conversions and boundaries, array/struct projection, one inner equijoin, and selected DDL/error cases. These are finite cases for the `spark35-local-v1` profile, not a general type-by-operator compatibility statement. Known gaps include UTC-aware timestamp-column comparison with a naive literal (robin-sparkless #1714), nested-field SQL resolution (#1715), map constructors, array indexing, broader collection operators, outer/self/multiple joins, and general SQL semantics. See the [B019.1 aggregate](B019.1-sql-semantics-corpus.md).

Selected utilities are `DESCRIBE TABLE`, `DESCRIBE HISTORY` and literal-integer `VERSION AS OF`. Description output covers top-level field names/types/comments; history yields the selected seven-column provider profile for at most 100 newest records. Extended/detail descriptions and an arbitrary history limit are unsupported. Snapshot timestamp selectors and parameterized selectors are unsupported; missing, future and expired integer versions raise typed errors without reading latest.

`SHOW TABLES`, `EXPLAIN SELECT`, `ANALYZE TABLE`, `OPTIMIZE`, and `VACUUM` have no route in the current profile. Each is covered by `test_unselected_sql_utilities_reject_without_table_side_effects`; all five raise `UnsupportedSqlStatementError`, preserve the catalog registration, and preserve the Delta version. The existing `test_ctas_query_execution_errors_do_not_register_target` verifies that a query-engine exception is propagated before CTAS registration. No fallback or fabricated result is used.
