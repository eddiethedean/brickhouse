## Contract exercised

Each job runs a real Python producer that reads task parameters through worker-scoped widgets, reads an explicitly granted secret, and appends a typed order to the same registered Delta table. A declared dependent Python task reads both the committed order and the upstream task value. The test checks both tasks' actual captured output, their run context, the schema and values at each Delta version, and the final table through a fresh Sparkless session.

The matrix covers serverless plus classic standard and classic dedicated selections, each using new, existing, and shared resource selectors where applicable. The two tasks in a `new` selection each receive their own requested resource, so two resources are started and terminated. A shared resource has two consumers and terminates only after both release. Existing all-purpose resources retain their identity and remain running after both tasks complete. Serverless has no classic resource consumer or compute ID. Every classic worker's reported compute ID and profile matches its recorded consumer/resource; the resources are explicitly marked simulated.

The table advances from version 0 through version 7. Its final columns are `order_id: int64`, `authorized: bool`, and `source: string`; all eight expected rows (baseline plus seven profile runs) match delta-rs and a fresh Sparkless reader. The secret value is absent from retained output and workspace metadata.
