# B004.1 — Native Delta mutation candidate probe

## Environment

- Python: CPython 3.11.14 on macOS 26.5.2 ARM64
- Python mutation candidate: `deltalake` 1.2.1 (delta-rs Python package)
- PyArrow: 23.0.1
- Sparkless reader build: version 4.13.3 from `b73067252abd0720ea91ac447bfd3ce027e96a88`; its Cargo.lock pins Rust `deltalake`/`deltalake-core` 0.32.4
- Probe: [B004.1-delta-mutation-candidates.py](../probes/B004.1-delta-mutation-candidates.py)
- All files were synthetic and local under a temporary directory. No Databricks credentials, network, or remote compute were used.

## Real-file results

The probe created one Delta table with integer `id`/`amount` columns, then performed each operation through delta-rs. After every commit it opened the snapshot through Sparkless and compared sorted rows.

| Operation | delta-rs commit version | Result |
|---|---:|---|
| Create + read | 0 | Passed; Sparkless read all three initial rows |
| Append | 1 | Passed; new row visible through Sparkless |
| Update | 2 | Passed; `id = 2` amount changed from 20 to 21 |
| Delete | 3 | Passed; `id = 3` removed |
| Merge | 4 | Passed; matching `id = 2` updated to 22 and new `id = 5` inserted |

The merge returned metrics for two source rows, one inserted row, and one updated row. The final Sparkless snapshot matched `[(1, 10), (2, 22), (4, 40), (5, 50)]`; the Python process exited normally after stopping the Sparkless session.

## Candidate boundary

The Python `deltalake` 1.2.1 API successfully owned all tested transaction operations. Sparkless 4.13.3 with its bundled Rust delta-rs dependency read these committed snapshots. This is evidence for the primitive integer subset only. It does not prove Arrow/decimal/timestamp compatibility, advanced protocol/features, concurrent external writers, or general recovery. B004.2/B004.3 provide the later typed and bounded transaction-identity evidence.

Sparkless's Python `DataFrameWriter.save(path)` is not an alternative mutation route at this source revision: `.format("delta")` is ignored there and the method hardcodes Parquet. The behavior was reproduced in B003.2 and filed as [Sparkless issue #1684](https://github.com/eddiethedean/robin-sparkless/issues/1684). BrickHouse must delegate mutations to its table service and reject unsupported Sparkless write entry points; do not treat a successful method return as a Delta commit.

## Result

Selected phase 0.1 provider `deltalake` 1.2.1: **create/read/append/update/delete/merge passed** for local primitive tables, with Sparkless cross-reads after each committed version. B004.3 selects it with local protocol and recovery limits; this is not yet a BrickHouse table-service integration.
