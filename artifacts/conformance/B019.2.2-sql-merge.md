# B019.2.2 — Single-key SQL MERGE

Date: 2026-10-21  
Result: **passed locally** for one registered source/target Delta table, one equality key, matched update, and unmatched insert.

## Environment

- Python 3.11.14
- Sparkless 4.15.0
- `deltalake==1.2.1`
- PyArrow 23.0.1
- SQLGlot 30.24.0
- Databricks SDK 0.153.0
- SQLite 3.53.4; workspace metadata schema 19

## Implemented behavior

The SQL planner binds a registered Delta target and source and accepts exactly one qualified target-key/source-key equality, one unconditional `WHEN MATCHED THEN UPDATE`, and one unconditional `WHEN NOT MATCHED THEN INSERT`. The insert must explicitly map every target field from one source field. The selected contract requires identical source/target Delta schemas and matching Arrow types for mapped fields. Source keys are non-null and unique; duplicates reject before target journal preparation.

Execution materializes the exact registered source snapshot through `DeltaRsTableService`, fingerprints its table identity, version, schema, and Arrow contents, and calls the public delta-rs 1.2.1 native MERGE builder. The journal records the target snapshot fence and application transaction. Delta history records the operation identity and exact insert/update counts; the journal recovers `rows_affected` as inserted plus updated. One MERGE operation produced one committed Delta version, preserved the exact target Arrow schema, and was visible through a fresh Sparkless SQL query.

Metadata schema 19 adds `sql_merge` to the operation journal and transactionally preserves existing schema-18 operation records. The migration suite also exercises prior schema-17 operation records upgrading through schema 18 to 19.

## Evidence

- `tests/unit/test_sql_merge.py::test_single_key_merge_commits_once_and_is_visible_through_sparkless`: exact updated/inserted rows, schema, Delta history metadata and metrics, one commit version, operation-journal identity, and fresh Sparkless query visibility.
- `tests/unit/test_sql_merge.py::test_unsupported_or_invalid_merge_has_no_target_side_effects`: rejects unsupported actions, source-side unmatched action, multi-key predicates, unknown target fields, and incomplete insert mappings without changing the target or creating a target journal record.
- `tests/unit/test_sql_merge.py::test_merge_rejects_duplicate_source_keys_before_target_journaling`: typed duplicate-key rejection leaves target/source versions unchanged and does not create a target journal record.
- `tests/unit/test_sql_merge.py::test_merge_rejects_missing_target_before_provider_dispatch`: typed invalid-target rejection.
- `tests/unit/test_delta_operation_journal.py::test_metadata_schema_17_operation_records_migrate_through_schema_19`: preserves journal records through the schema-18 and schema-19 upgrades.
- The combined focused SQL/provider/workspace regression run passed **110 tests**.

The suite ran with `DATABRICKS_TOKEN`, `DATABRICKS_HOST`, and `DATABRICKS_PROFILE` unset. It used real local Delta tables and the pinned local Sparkless engine; no Databricks workspace or cloud compute was contacted.

## Limits

Source subqueries, self-merges, multi-key or residual ON predicates, conditional clauses, delete clauses, star inserts, arbitrary expression mappings, differing source/target schemas, and general Spark/Databricks MERGE parity remain unsupported or unqualified. SQL DESCRIBE/HISTORY and VERSION AS OF remain B019.2.3 and B019.2.4.
