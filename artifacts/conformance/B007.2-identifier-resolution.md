# B007.2 — Identifier resolution and isolated namespace defaults

Date: 2026-10-19

## Result

Added a Spark-style identifier parser and `NamespaceState` resolver. It parses one-to-three-part names, treats a dot inside backticks as part of the name, handles doubled backticks, preserves parsed spelling, and performs case-insensitive lookup. One-part table names use current catalog/schema, two-part names use current catalog plus schema/table, and three-part names use explicit catalog/schema/table. It never drops an unrecognized leading catalog. Schema names accept one or two parts.

`WorkspaceContext.new_namespace_state()` creates new state from the workspace config each time. Namespace changes are local to that object; `use_catalog` resets schema to `default`, and `use_schema` validates before changing either current value. Unknown names raise `NamespaceNotFoundError` or `TableNotFoundError`; case-insensitive duplicate matches raise `AmbiguousIdentifierError`; malformed syntax or unsupported arity raises `InvalidIdentifierError`.

The reference capture in [B007.2-identifiers-reference.md](B007.2-identifiers-reference.md) submitted one literal-only statement to the existing SQL warehouse. It confirmed current catalog/schema were non-null and verified alias spelling for a dotted part and embedded backtick. It masked the actual catalog/schema strings and restored the warehouse to STOPPED. It did not test table lookup or change account data. The [Databricks query reference](https://docs.databricks.com/aws/en/query/) and [Spark 3.5.8 identifier reference](https://spark.apache.org/docs/3.5.8/sql-ref-identifier.html) define the broader rules used to shape this limited profile.

## Limits

This is a namespace-state and catalog binding primitive, not SQL parsing or a running Spark/Databricks session. Temporary views, SQL Path, built-in system namespaces, catalog/schema CRUD, API routes, Sparkless session integration, and actual Delta data access remain unimplemented.
