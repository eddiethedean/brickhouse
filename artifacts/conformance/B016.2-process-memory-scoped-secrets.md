# B016.2 — Process-memory scoped secrets

Date: 2026-10-20

## Result

B016.2 adds an explicitly configured process-memory secret provider and a real worker-facing `dbutils.secrets` subset. Only scopes granted to the submitted job are included in the one-attempt payload. Values are sent over a private one-way stdin pipe, excluded from the immutable context/environment/metadata, and exact raw occurrences are redacted from retained stdout/stderr before persistence.

## Checks

- Provider snapshots contain only scopes granted to the selected job; values and grants are bounded and do not enter the worker context.
- Worker methods return configured values and metadata. Unauthorized scopes fail with `PermissionError`; missing keys in authorized scopes fail with `KeyError`.
- An actual pinned SDK job resolves an approved key, sees only the approved scope/key metadata, receives denied/missing errors for other lookups, and prints the secret without retaining its bytes in SDK output or workspace metadata.
- A direct fresh worker consumes the one-way pipe, reports no secret in its immutable context, and has its exact printed value redacted before outcome capture.
- Workspace close clears the provider. No Databricks credentials, account calls, cloud compute, Spark, JVM, or `.env` access was used.
