# B006.3 — CLI and embedded lifecycle evidence

Date: 2026-10-19

## Result

Added the public `brickhouse.Workspace.local(directory)` context. Entering validates an existing version 1 workspace and acquires its POSIX owner lock; exiting releases ownership. The CLI uses this same context for `serve`. `init` creates workspaces, `capabilities` and `doctor` report package/runtime and provider metadata, and `serve` exposes only `/health`, `/version`, and `/capabilities` over IPv4 loopback. Ctrl-C and SIGTERM release the owner lock. Installed Sparkless/delta-rs distributions are reported as `not_integrated`; the diagnostic path does not import provider code or load Databricks credentials.

The `run` command is present as an explicit unavailable operation. It exits nonzero and never starts the requested script because job supervision belongs to B013. The embedded context exposes the validated workspace descriptor; it does not yet provide a session. The diagnostics server does not implement Databricks SDK, catalog, SQL, table, or job endpoints.

## Scope limits

The owner lock is verified only on local POSIX filesystems. The unauthenticated diagnostics server binds only IPv4 loopback. Workspace format 1 has no older-version upgrade path. Catalog/SQL/data-provider services, `Workspace.session()`, job execution, and Databricks client compatibility remain unimplemented.
