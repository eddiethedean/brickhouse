# B008.1 — Table contracts and workspace-owned staging

Date: 2026-10-19\
Status: passed local acceptance\
Profile: BrickHouse `0.1.0.dev0`; Python 3.11.14; SQLite 3.53.4; `deltalake==1.2.1`; `pyarrow==23.0.1`; workspace format 1; metadata schema 3.

## Scope

The tests create a real local Delta table with nested list data, append a second commit, register its local path as an external table, and construct a `TableHandle` and versioned `TableSnapshot` using the public delta-rs table version, schema JSON, and protocol values. They load a selected historical version and verify stable namespace/table IDs, canonical location, schema fingerprint, version, and the initial protocol envelope.

Separate local cases exercise version/timestamp selector validation; protocol and feature rejection; create/append/overwrite target rules; strict schema compatibility; unsupported-mode errors; and copying a real Parquet file into workspace-owned staging. Staging checks byte-for-byte content, PyArrow Parquet readability, SHA-256, byte count, file permissions, path ownership, safe cleanup, and missing-source failure.

No `.env`, Databricks credential, remote service, Sparkless execution, or BrickHouse provider-backed Delta read/write was used. Delta table creation and append in the snapshot test are direct local delta-rs fixture setup, not BrickHouse table-service operations.

## Implemented contract

- `TableHandle` maps the persistent catalog/schema/table IDs, names, ownership, and canonical local location.
- `SchemaDescriptor` canonicalizes full nested Delta schema JSON and computes a stable SHA-256 fingerprint.
- `TableSnapshot` captures one Delta version, the schema, normalized protocol, and timezone-aware capture time.
- `SnapshotSelector` accepts latest, one nonnegative version, or one aware timestamp.
- `DeltaProviderProfile` accepts reader/writer protocol 1/2 with no features and declares create, append, and overwrite modes.
- `validate_write_request()` rejects duplicate create, missing append/overwrite targets, unsupported modes/protocol/features, and mismatched schemas.
- `StagingArea` copies labeled Parquet/Arrow IPC input to a random private workspace directory and removes only a verified workspace-owned artifact.
- The `TableServicePort` is a protocol only. Table reads/writes and schema inspection through BrickHouse are not implemented.
