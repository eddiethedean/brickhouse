# B015.1.2 profile-bound worker SparkSession

Date: 2026-10-21

## Scope

When a managed worker imports `pyspark.sql`, BrickHouse validates the resolved
compute profile and creates one Sparkless session on the worker's main thread.
It applies the immutable effective settings before the import returns. The
worker facade exposes `SparkSession.builder.config(...).getOrCreate()`,
`createDataFrame`, `range`, bounded read-only SQL, and the supported configuration
keys. Serverless settings require ANSI mode and UTC; classic execution is limited
to the mapped `spark35-local-v1` standard or dedicated profiles with explicit
ANSI/timezone settings. Unsupported master/JVM/RDD APIs and unmapped settings
raise BrickHouse errors. Worker cleanup stops the native session on its creating
thread, including when user code raises.

Plain Python workers do not load Sparkless or reject otherwise valid plain Python
work merely because the selected classic compute request has no Spark SQL settings.
Spark profile configuration is validated when the script requests `pyspark.sql`.

## Local checks

Command:

```text
env -u DATABRICKS_TOKEN -u DATABRICKS_HOST PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 PYTHONPATH=src /tmp/brickhouse-plan-audit/bin/python -m pytest -q tests/unit/test_worker_imports.py tests/unit/test_worker.py tests/unit/test_worker_session.py tests/unit/test_worker_auth.py tests/unit/test_secrets.py tests/unit/test_jobs_api_sdk.py::test_sdk_binds_workers_to_all_seven_compute_variants
```

Result: **46 tests passed**. Real fresh workers ran a DataFrame filter/select/count
under the serverless profile and the mapped classic-standard profile, observed the
resolved settings before user operations, rejected unsupported Spark/RDD calls,
unsupported settings and an unmapped classic runtime, and enforced session
thread ownership. The existing pinned-SDK loopback test also passed all seven
serverless/classic worker request variants, including plain Python classic jobs
without Spark settings. Worker authentication and secrets regressions passed.
Ruff check/format and strict mypy passed; Databricks credentials were unset.

## Limits

The builder supports only validated `.config(key, value)` and
`.getOrCreate()`; `appName`, `master`, and `option` are explicit unsupported
operations. The session does not yet resolve registered tables, expose a reader,
or expose the catalog; B015.1.3 owns authenticated table binding. This does not
claim Spark Connect or remote Databricks runtime compatibility.
