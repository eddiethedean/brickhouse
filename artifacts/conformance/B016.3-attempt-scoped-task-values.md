# B016.3 — Attempt-scoped task values

Date: 2026-10-20

## Result

Python SDK script workers now use `dbutils.jobs.taskValues.set/get` through a private authenticated socket to the parent repository. Metadata schema 10 persists compact finite JSON by run, task, attempt, and key. The parent permits 250 distinct task/key pairs per run and values up to 48 KiB. Failed-attempt values remain attributable to that attempt but only successful upstream attempts are visible to downstream readers. An SDK loopback workflow verified retry selection, defaults, `null`, missing-task errors, unrelated-task denial, unsupported methods, worker environment cleanup, and run isolation.

The implementation follows the documented task-value method rules as a local Python script-task extension. Databricks documents the utility for Python notebooks; this evidence does not claim notebook behavior or cloud parity. Per-attempt stdout/stderr continues to be captured by the existing worker output contract. Notebook exit/results and notebook context getters remain B017 scope.

## Checks

- Repository tests prove per-attempt retention, successful-attempt selection, null-versus-missing behavior, transitive upstream authorization, run isolation, the exact 48 KiB serialized limit, and the 250-value run limit.
- A pinned `databricks-sdk==0.153.0` loopback job writes a value then fails, retries with a different value, and confirms the dependent task reads only the successful attempt. It also verifies fallback/default behavior, explicit errors, denied access to a successful unrelated peer, and no task-value leakage between runs.
- Metadata upgrade fixtures cover schema 8, 7, 3, and 1 through schema 10; workspace opening rejects an incomplete task-value constraint schema.
- No Databricks credentials/account, cloud compute, Spark, JVM, or `.env` was used.

## Limits

- The SDK's multi-task output endpoint remains unsupported; outputs are available from the existing internal per-attempt repository.
- Only task value `set/get` are implemented. For-each aggregation, notebook results, notebook context getters, mounts, and other `dbutils.jobs` methods remain unsupported.
- Task values are durable job metadata and are not a secret store. The private socket transport is POSIX-only and has no public HTTP route.
