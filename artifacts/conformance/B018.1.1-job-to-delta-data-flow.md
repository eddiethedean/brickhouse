# B018.1.1 — SDK job-to-Delta dependent data flow

**Status:** passed locally on 2026-10-21  
**Scope:** one pinned-SDK Python job on the local classic-standard profile. The SDK client used the BrickHouse loopback server. This is not a Databricks-account or cloud-compute test.

## Contract exercised

An SDK job uploads and runs a parameterized Python producer. The producer resolves a job-granted secret, creates rows with explicit `LongType`, `BooleanType`, and `StringType` columns, and appends them to an existing registered Delta table through:

```python
frame.write.format("delta").mode("append").saveAsTable("main.default.job_orders")
```

The declared dependent task reads the writer's task value and the committed table through its own worker Sparkless session. The test checks each worker's persisted stdout, then verifies the same schema and rows from a new parent Sparkless session and a pinned-SDK SQL Statement Execution request. The Delta version advances from 0 to 1.

The worker writer only accepts Delta append to an existing registered table. It sends at most 32 KiB of Arrow IPC and 100,000 rows in the 64 KiB authenticated worker protocol. The parent re-resolves the table and checks its stable table ID, canonical location, and expected Delta version before calling the journaled `DeltaRsTableService.write_arrow()` with append mode and an optimistic version check. Worker table creation, overwrite, path writes, options, partitions, and SQL mutations remain unsupported.
