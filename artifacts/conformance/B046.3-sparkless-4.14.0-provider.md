## Confirmed failing contracts

The independent [nullable-struct reproducer](../probes/B046.3-null-struct-repro.py) checks three distinct values: `{"label": "present"}`, a null struct, and `{"label": null}`. It compares decoded provider IPC and whole collected rows, including direct native Delta input to avoid conflating ingestion with result conversion.

```bash
/tmp/brickhouse-sparkless-4140/bin/python artifacts/probes/B046.3-null-struct-repro.py --output artifacts/conformance/B046.3-null-struct-repro.json
```

Result: **exit 1; five failed comparisons and one passing control**; [raw synthetic observations](B046.3-null-struct-repro.json). These are actual failures, not skips or expected-failure markers.

| Contract | Observed result | Issue |
|---|---|---|
| Python/Arrow ingestion → provider IPC retains parent validity | Null struct becomes `{"label": null}` in both entry paths; actual table-service commit also persisted that difference in the initial integration run | [#1694](https://github.com/eddiethedean/robin-sparkless/issues/1694) |

Both issue bodies contain standalone snippets that were executed against this exact wheel and failed at the stated assertions. The IPC capture callback deliberately raises before mutation; it never reports a successful write. No matching issue for these exact contracts was found in repository searches; related closed #1066 concerns other struct operations.

## Remaining limits and next action

B046.3 and its parent stay blocked until the exact nullable-struct repros and the combined Delta/provider probe pass against a recorded compatible artifact. B046.1 and B046.2 retain their scoped source/API and callback-suite evidence. B010 must still implement the production adapter, namespace/schema conversion, service error mapping and rejection of unprotected writer paths. StructType JSON parsing is not a verified public API: this probe uses an explicit limited conversion through public type constructors and rejects other types.

Inputs are tiny synthetic local data: two rows per batch, callback limits of 32 rows/1 MiB. The native writer buffers the full frame before callback limits apply; there is no streaming or bounded-memory claim. Native sessions stay on their owner threads; no cross-thread transfer is attempted. Callbacks synchronously acquire the GIL and wrap Python exceptions as native errors. Process termination proves containment and real committed outcomes, not asynchronous callback cancellation or the future job API. No `.env`, Databricks account, remote compute or JVM was used.
