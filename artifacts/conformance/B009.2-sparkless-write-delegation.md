## Contract implemented

The engine-neutral Rust API now defines `ArrowIpcStream`, `ExternalTableSaveMode`,
`ExternalTableWriteRequest`, and `ExternalTableWriteResult`. The default provider
write hook returns an explicit unsupported error. A successful receipt must preserve
the resolved table identity and identify its exact nonnegative, monotonic committed
version.

The Polars `DataFrameWriter.saveAsTable()` path delegates append and overwrite to a
resolved external provider. Existing session tables and temp views shadow that
provider; `ErrorIfExists` rejects an existing external table, and `Ignore` is a no-op.
The request carries a buffered Arrow IPC stream, selected format, caller writer
options, and resolved partition columns. Provider errors and invalid receipts surface
without a local write fallback. SQL `INSERT INTO` delegates append through the same
hook.

Tests use real local Delta fixtures and cover scalar/nested typed transfer (decimal,
date, timestamp, array, and struct), append/overwrite modes, format/options, exact
commit versions, SQL insert, non-mutating modes, and provider failure without table
mutation. The external Delta read path also rejects the ordinary Parquet compatibility
fallback, so a non-Delta directory is not accepted as a declared Delta snapshot.

## Availability and limits

Commit `4923b857b0208a5d81116e7782f17110d4558eb6` is pushed to PR #1692, which is
open and unmerged. Neither the new read hooks nor write hooks are in published
Sparkless 4.13.4. The writer buffers one Arrow IPC stream in memory and invokes a
synchronous Rust provider; there is no Python binding or async/network transport.
Path-based `save()`, `insertInto()`, SQL `UPDATE`/`DELETE`, and Sparkless logical Map
writes are not delegated. BrickHouse has not integrated or claimed support for these
hooks.
