# B014.1 — Durable job definitions, submissions, and attempts

Date: **2026-10-20**. Task: **done**. Decision: [ADR 0022](../../docs/decisions/0022-durable-job-state.md).

## Behavior

Added `WorkspaceContext.jobs`, backed by metadata schema 6. The repository stores immutable job/task definitions, immutable submitted settings and per-run task graph snapshots, optional workspace-wide idempotency tokens, fingerprints, state, timestamps, error codes, attempt numbers and distinct attempt UUIDs. Jobs contain one to ten Python-script task definitions with validated acyclic dependencies. Settings are finite canonical JSON bounded to 64 KiB per object; credential-shaped setting keys are rejected.

SQLite foreign keys, checks and triggers enforce legal run/task/attempt transitions, dependency-consistent terminal run results, immutable submitted definitions, and immutable terminal history. Failed tasks may receive another distinct attempt while the run is active. Worker results map observed exit codes to truthful terminal outcomes. Explicit interruption records unknown exit status as null, interrupts only active/queued task work, and leaves undispatched tasks pending. Workspace metadata from schemas 1–5 migrates transactionally to schema 6 under the existing workspace-owner path.

This slice is only a state contract. It does not execute tasks, expose SDK/HTTP job routes, retrieve durable logs/output, schedule tasks, enforce concurrent queue limits, apply automatic retries, or reconcile active runs after restart. `brickhouse run` remains explicitly unavailable until later B014 work composes dispatch.
