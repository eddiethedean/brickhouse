# B007.2 — Databricks identifier reference capture

Date: 2026-10-19

## Question and limits

Can the existing Databricks SQL warehouse evaluate `current_catalog()` and `current_schema()` in a literal-only statement, and does it accept backtick aliases with a dotted part and an escaped backtick?

One reviewed statement was submitted to the existing stopped serverless 2X-Small SQL warehouse. It returned one row, completed in about 10 seconds, and the warehouse was restored to `STOPPED`. The actual catalog/schema values were reduced in the capture to `present`; no workspace, catalog, schema, table, or file was created or changed. The account's warehouse engine version was not exposed. This reference observation is not a BrickHouse runtime test.

## Operation

```sql
SELECT current_catalog() AS catalog_context,
       current_schema() AS schema_context,
       1 AS `simple`,
       2 AS `part.with.dot`,
       3 AS `mixed``tick`
```

The sanitized result schema contained `catalog_context STRING`, `schema_context STRING`, `simple INT`, `part.with.dot INT`, and `mixed\`tick INT`; all three literal results were returned. Both context functions returned a non-null value, but their actual names were intentionally redacted.

The probe uses the same bounded SQL Statement Execution API 2.0 capture tool as B005.3, a single statement, a 75-second wait limit, and no persisted response containing account identifiers.

## Local design implications

- Use backticks for delimited parts and doubled backticks for an embedded backtick. Dots inside a quoted part are data, not separators.
- Treat names as case-insensitive for lookup while preserving parsed spelling. Unity Catalog stores object names lowercase; special characters require quoting, and period/space/slash remain disallowed in UC object names.
- Resolve one-part tables against the session's current catalog and schema, two-part names against the current catalog and explicit schema, and three-part names against the explicit catalog and schema. A fully qualified name is never shortened by stripping a leading component.
- Keep current catalog/schema values in a fresh state object for each session. `USE CATALOG` resets the schema to `default`; `USE SCHEMA catalog.schema` updates both values.
- This capture verifies SQL parser acceptance and the existence of context values only. The documented name-resolution rules come from the Databricks SQL and Spark 3.5 references below. BrickHouse's deterministic local tests exercise its implementation and errors.
